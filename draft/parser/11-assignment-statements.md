# Parser 议题 11：赋值语句

> 状态：已确认；赋值左侧按普通 `expression` 解析，可写性由语义分析检查
> 确认日期：2026-08-03

## 1. 赋值是语句

Ink 的赋值是独立语句，不是表达式：

```ebnf
assignment_statement =
    expression, assignment_operator, expression, ";" ;

assignment_operator =
    "="
  | "+=" | "-=" | "*=" | "/=" | "%="
  | "&=" | "|=" | "^="
  | "<<=" | ">>=" ;
```

Parser 不定义 `assignment_target` 或 `place_expression` 非终结符。左侧先建立普通 Expression CST；名称绑定、重载选择和值类别确定以后，语义分析再检查它是否表示当前上下文中的可写存储位置。

因此下列语句语法成立，但语义检查失败：

```ink
1 = 2;
true = false;
```

反过来，若 `slot()` 的结果类型是可写 `T&`，`slot() = value;` 可以通过语义检查。仅凭函数调用的语法形状无法判断它是不是 place。

这与取地址表达式采用相同边界：Parser 负责识别表达式结构，语义阶段负责判断表达式是否产生 place，以及该 place 是否可写。

## 2. 普通赋值

普通赋值写入一个目标：

```ink
value = 10;
object.field = value;
array[index] = value;
pointer->field = value;
```

右侧表达式按照既有构造、复制、类型转换和不可复制规则写入目标。赋值不会通过隐藏移动消费一个命名右值。

覆盖已有值时的赋值操作、析构与异常安全由值和类型语义决定，不改变本节的单目标语法。

## 3. 赋值不产生结果值

赋值只能出现在允许 `assignment_statement` 的位置，不能嵌入初始化器、调用实参、条件或其他表达式：

```ink
var a = 0;
a = 10;           // 合法

const x = (a = 10); // 非法
consume(a = 10);  // 非法
if (a = 10) { }     // 非法
```

这避免把条件比较误写成赋值，也不需要定义赋值表达式返回目标引用、写入后的值还是原始右值。

## 4. 禁止链式赋值

每条赋值语句准确包含一个左侧表达式、一个 `assignment_operator` 和一个右侧表达式。链式赋值非法：

```ink
a = b = value;
x = y = z = 0;
```

应拆成明确的独立语句，并由源码顺序表达执行顺序：

```ink
b = value;
a = b;
```

Ink 不定义链式赋值的右到左传播、中间类型转换、部分更新或不可复制值传播规则。

## 5. 禁止多目标赋值

普通赋值不提供逗号分隔目标或元组解构语义：

```ink
a, b = 1, 2;
(a, b) = pair;
(a, b) = (b, a);
```

`a, b = 1, 2;` 不能组成上述单表达式 EBNF。`(a, b) = pair;` 和 `(a, b) = (b, a);` 的左侧可以先解析成普通元组表达式，但该表达式不是可写 place，因而语义检查失败。

未来如果增加解构赋值，必须使用独立产生式并定义其复制、借用、临时对象和失败语义，不能把普通元组表达式悄然解释为多个写入目标。

## 6. 复合赋值

复合赋值同样只有一个目标：

```ink
count += 1;
mask &= allowed;
value <<= shift;
```

概念上它读取目标当前值、执行对应操作并写回同一位置，但不是简单源码展开。目标位置只求值一次：

```ink
array[next_index()] += value;
```

`next_index()` 只能执行一次。具体运算继续遵守对应算术、位运算、溢出、移位和运算符解析规则。

复合赋值不产生值，因此也不能嵌入其他赋值或表达式：

```ink
a = b += 1;
a += b += 1;
```

这些形式非法。

## 7. 求值顺序

一条赋值语句按照源码从左到右建立求值顺序：

1. 计算目标存储位置所需的基址、成员和索引，每部分只计算一次；
2. 计算右侧表达式一次；
3. 执行普通或复合赋值并写入目标。

例如：

```ink
array[next_index()] = make_value();
```

先执行 `next_index()` 并固定目标位置，再执行 `make_value()`，最后写入。右侧求值失败时不会发生最终写入，但目标位置求值已经产生的普通副作用不会回滚。

## 8. 可写性

赋值目标必须具有当前上下文允许的写访问能力。至少包括：

- `var` 绑定；
- 可写对象的可写字段；
- 可写数组、切片或索引位置；
- 通过 `T*`、`T&` 等可写访问路径取得的位置。

`const` 绑定本身不能重新赋值；`const T*`、`const T&` 或其他只读访问路径不能用于写入目标。指针绑定是否可重新赋值与其指向对象是否可写仍是两项独立能力。

可写性完全是语义检查，不改变 Parser 已经建立的左侧 Expression CST，也不要求 Parser 将表达式提前改写成专用目标节点。

## 9. 符号邻接

Tokenizer 将符号逐字符输出。Parser 根据议题 02 识别直接相邻的复合赋值符号：

```ink
value += 1;  // "+="
value <<= 2; // "<<="
```

符号内部不能包含 Trivia：

```ink
value + = 1;
value < < = 2;
```

这些形式不匹配复合赋值运算符。

## 10. 不支持自增与自减运算符

Ink 不定义前缀或后缀 `++`、`--` 运算符：

```ink
++value;
value++;
--value;
value--;
```

这些形式均非法。递增和递减统一使用无结果的复合赋值语句：

```ink
value += 1;
value -= 1;
```

因此 Ink 不需要区分前缀与后缀形式，也不存在“返回修改前的值”或“返回修改后的值”的自增、自减表达式。副作用不能借此嵌入初始化器、索引、实参或其他表达式。

Tokenizer 仍会忠实地产生两个相邻的 `Symbol('+')` 或 `Symbol('-')` Token；Parser 不把它们组合成自增、自减运算符。

## 11. CST 与恢复

赋值 CST 保留左侧表达式、构成运算符的全部单字符 Symbol Token、右侧表达式和结尾分号，不建立 `AssignmentTarget` 节点。Parser 在 statement fallback 中先解析一个普通表达式，再根据紧随其后的连续符号序列区分赋值语句与普通表达式语句：

```text
left = parse_expression()

if next tokens form assignment_operator:
    operator = parse_assignment_operator()
    right = parse_expression()
    expect ";"
    return AssignmentStatement(left, operator, right)

expect ";"
return ExpressionStatement(left)
```

赋值运算符不属于表达式优先级，所以 `parse_expression()` 会在 `=`、`+=` 等 Token 之前自然停止。该分流只发生在允许语句的入口；括号、实参、初始化器和条件内部仍只调用表达式 Parser，因此不会接受嵌入式赋值。

如果一个赋值运算符之后再次遇到赋值运算符，Parser 不建立链式节点，而是按照议题 03 把后续非法结构保存在 `ErrorNode` 中并同步到语句结束位置。

## 12. 确认结论

Ink 赋值是无结果的单目标语句。左右两侧都按普通表达式解析，左侧是否产生可写 place 由语义分析检查。支持普通赋值和常用算术、位运算、移位复合赋值；目标位置与右侧各求值一次。链式赋值、多目标赋值、赋值表达式、复合赋值链以及 `++`、`--` 均不支持。
