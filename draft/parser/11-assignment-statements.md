# Parser 议题 11：赋值语句

> 状态：已确认  
> 确认日期：2026-08-03

## 1. 赋值是语句

Ink 的赋值是独立语句，不是表达式：

```ebnf
assignment statement =
    assignment target, assignment operator, expression, ";" ;

assignment operator =
    "="
  | "+=" | "-=" | "*=" | "/=" | "%="
  | "&=" | "|=" | "^="
  | "<<=" | ">>=" ;
```

`assignment target` 的具体表达式形状由后续 place expression 议题定义；语义上它必须表示一个可写存储位置。

## 2. 普通赋值

普通赋值写入一个目标：

```ink
value = 10;
object.field = value;
array[index] = value;
pointer->field = value;
```

右侧表达式按照既有构造、复制、类型转换和不可复制规则写入目标。赋值不会通过隐藏移动消费一个命名右值。

覆盖已有值时的赋值操作、析构与异常安全由值和类型语义决定，不改变本节的单目标语法。

## 3. 赋值不产生结果值

赋值只能出现在允许 `assignment statement` 的位置，不能嵌入初始化器、调用实参、条件或其他表达式：

```ink
var a = 0;
a = 10;           // 合法

let x = (a = 10); // 非法
consume(a = 10);  // 非法
if a = 10 { }     // 非法
```

这避免把条件比较误写成赋值，也不需要定义赋值表达式返回目标引用、写入后的值还是原始右值。

## 4. 禁止链式赋值

每条赋值语句准确包含一个 `assignment target` 和一个 `assignment operator`。链式赋值非法：

```ink
a = b = value;
x = y = z = 0;
```

应拆成明确的独立语句，并由源码顺序表达执行顺序：

```ink
b = value;
a = b;
```

Ink 不定义链式赋值的右到左传播、中间类型转换、部分更新或不可复制值传播规则。

## 5. 禁止多目标赋值

普通赋值左侧不能是逗号分隔目标或元组目标：

```ink
a, b = 1, 2;
(a, b) = pair;
(a, b) = (b, a);
```

这些形式不属于本议题。未来如果增加解构赋值，必须使用独立产生式并定义其复制、借用、临时对象和失败语义，不能改变普通单目标赋值。

## 6. 复合赋值

复合赋值同样只有一个目标：

```ink
count += 1;
mask &= allowed;
value <<= shift;
```

概念上它读取目标当前值、执行对应操作并写回同一位置，但不是简单源码展开。目标位置只求值一次：

```ink
array[next_index()] += value;
```

`next_index()` 只能执行一次。具体运算继续遵守对应算术、位运算、溢出、移位和运算符解析规则。

复合赋值不产生值，因此也不能嵌入其他赋值或表达式：

```ink
a = b += 1;
a += b += 1;
```

这些形式非法。

## 7. 求值顺序

一条赋值语句按照源码从左到右建立求值顺序：

1. 计算目标存储位置所需的基址、成员和索引，每部分只计算一次；
2. 计算右侧表达式一次；
3. 执行普通或复合赋值并写入目标。

例如：

```ink
array[next_index()] = make_value();
```

先执行 `next_index()` 并固定目标位置，再执行 `make_value()`，最后写入。右侧求值失败时不会发生最终写入，但目标位置求值已经产生的普通副作用不会回滚。

## 8. 可写性

赋值目标必须具有当前上下文允许的写访问能力。至少包括：

- `var` 绑定；
- 可写对象的可写字段；
- 可写数组、切片或索引位置；
- 通过 `T*`、`T&` 等可写访问路径取得的位置。

`let` 和 `const` 绑定本身不能重新赋值；`const T*`、`const T&` 或其他只读访问路径不能用于写入目标。指针绑定是否可重新赋值与其指向对象是否可写仍是两项独立能力。

可写性是语义检查，不改变 Parser 对 assignment target CST 的构造。

## 9. 符号邻接

Tokenizer 将符号逐字符输出。Parser 根据议题 02 识别直接相邻的复合赋值符号：

```ink
value += 1;  // "+="
value <<= 2; // "<<="
```

符号内部不能包含 Trivia：

```ink
value + = 1;
value < < = 2;
```

这些形式不匹配复合赋值运算符。

## 10. 不支持自增与自减运算符

Ink 不定义前缀或后缀 `++`、`--` 运算符：

```ink
++value;
value++;
--value;
value--;
```

这些形式均非法。递增和递减统一使用无结果的复合赋值语句：

```ink
value += 1;
value -= 1;
```

因此 Ink 不需要区分前缀与后缀形式，也不存在“返回修改前的值”或“返回修改后的值”的自增、自减表达式。副作用不能借此嵌入初始化器、索引、实参或其他表达式。

Tokenizer 仍会忠实地产生两个相邻的 `Symbol('+')` 或 `Symbol('-')` Token；Parser 不把它们组合成自增、自减运算符。

## 11. CST 与恢复

赋值 CST 保留目标、构成运算符的全部单字符 Symbol Token、右侧表达式和结尾分号。Parser 在识别目标表达式后，根据下一个连续符号序列区分赋值语句与普通表达式语句。

如果一个赋值运算符之后再次遇到赋值运算符，Parser 不建立链式节点，而是按照议题 03 把后续非法结构保存在 `ErrorNode` 中并同步到语句结束位置。

## 12. 确认结论

Ink 赋值是无结果的单目标语句。支持普通赋值和常用算术、位运算、移位复合赋值；目标位置与右侧各求值一次。链式赋值、多目标赋值、赋值表达式、复合赋值链以及 `++`、`--` 均不支持。
