# Parser 议题 13：表达式求值顺序

> 状态：已确认，Parser 议题 15 补充命名实参与默认值求值顺序
> 确认日期：2026-08-03

## 1. 统一规则

Ink 的表达式子项按照源码从左到右求值。只要两个子表达式都需要执行，源码中位于左侧的子表达式必须先完成，右侧才能开始。

```ink
left() + right();
```

顺序固定为：

```text
left()
→ right()
→ 执行加法
```

该规则属于 Ink 抽象机语义，不能由具体后端、优化级别或目标平台任意选择。

## 2. 二元运算

普通二元运算先完整计算左操作数，再完整计算右操作数，最后执行运算：

```ink
make_left() * make_right()
```

顺序为：

```text
make_left()
→ make_right()
→ 乘法
```

议题 12 规定的结合性决定表达式树，求值顺序再应用于该树。例如：

```ink
a() - b() - c()
```

解析为 `(a() - b()) - c()`，并按照 `a()`、`b()`、第一次减法、`c()`、第二次减法的顺序执行。

## 3. 短路逻辑运算

`&&` 和 `||` 仍遵守从左到右规则，但右操作数可能不执行：

- `left && right`：先计算 `left`；只有结果为 `true` 才计算 `right`；
- `left || right`：先计算 `left`；只有结果为 `false` 才计算 `right`。

```ink
pointer != null && pointer->ready()
cached || load_cache()
```

这不是一般求值顺序的例外，而是运算符自身确定右操作数是否需要求值。

## 4. 调用

函数调用先计算被调用对象，再按照源码顺序从左到右计算全部显式位置实参、列表展开和命名实参：

```ink
select_function()(first(), second(), third());
```

顺序为：

```text
select_function()
→ first()
→ second()
→ third()
→ 进入被调用函数
```

普通直接函数名本身通常不产生运行时动作，但仍占据被调用对象的位置；该规则同样适用于函数值、函数指针、虚函数、接口调用和其他可调用对象。

命名实参改变参数绑定位置，不改变求值顺序：

```ink
connect(second = make_second(), first = make_first());
```

仍然先执行 `make_second()`，再执行 `make_first()`。参数名称是否重复、能否绑定目标声明以及省略位置如何由默认值补全，由语义分析确定。

成员调用先计算接收对象，再从左到右计算实参：

```ink
make_object().process(first(), second());
```

顺序固定为 `make_object()`、`first()`、`second()`，然后进入 `process`。

省略的普通默认实参在对应调用处执行。调用先从左到右计算全部显式实参，再按照形参声明顺序从左到右计算尚未绑定参数的默认表达式；命名实参可以跳过某个具有默认值的参数并显式绑定其后的参数。

## 5. 索引、成员访问与后缀链

索引先计算被索引的基础表达式，再计算索引表达式：

```ink
make_array()[next_index()]
```

先执行 `make_array()`，再执行 `next_index()`，最后进行索引访问。

成员访问先计算左侧对象、引用或指针，再进行成员选择。连续后缀操作按照表达式树从左到右逐步建立：

```ink
make_container().items[next_index()].read()
```

后续议题会定义后缀表达式的完整语法，但不能改变本节的求值顺序。

## 6. 聚合表达式

元组、数组以及其他按源码列出元素的值表达式，按照元素出现顺序从左到右求值并构造：

```ink
[first(), second(), third()]
(first(), second(), third())
```

每个元素只在前一个元素求值并构造完成后开始。已经构造部分的清理由对应值类型和 RAII 规则处理。

## 7. 条件表达式

`if` 表达式先计算条件，然后只计算被选择的一个分支：

```ink
const value = if (condition()) when_true() else when_false();
```

`condition()` 为 `true` 时只执行 `when_true()`；为 `false` 时只执行 `when_false()`。未选择的分支不产生任何运行时或编译期效果。

## 8. 赋值顺序

赋值继续采用议题 11 已确认的专门顺序：

```text
计算目标位置所需的基址、成员和索引
→ 计算右侧表达式
→ 写入目标
```

目标位置内部的多个子项仍按照源码从左到右求值。例如：

```ink
make_array()[next_index()] = make_value();
```

顺序为 `make_array()`、`next_index()`、`make_value()`，最后写入。

## 10. 编译期与运行时一致

相同 Ink 表达式在编译期执行和运行时执行时使用相同的求值顺序：

```ink
comptime compile_time_call(first(), second());
runtime_call(first(), second());
```

`comptime` 不能把实参顺序、短路行为或未选择分支改成另一套语义。编译期允许的文件读取、反射、声明展开等效果同样按照源码顺序发生。

## 11. 优化器边界

编译器可以重排或合并无法被程序观察到的纯计算，但优化后的程序必须与规定的从左到右抽象执行结果等价。

优化不能改变：

- 可观察的读写和其他副作用顺序；
- 函数调用和外部操作的可观察顺序；
- 短路后右操作数是否执行；
- 编译期执行产生效果的顺序。

因此该规则确定程序语义，但不禁止编译器在证明等价时进行指令调度、常量折叠或删除无效果计算。

## 12. Parser 与 CST

Parser 按议题 12 构造无歧义的表达式树；从左到右求值由树中有序子节点和本议题的语义共同确定。CST 不需要插入表示求值顺序的隐藏 Token 或节点。

括号会改变表达式树，但不会把同一节点内部的子项改成从右到左求值：

```ink
a() * (b() + c())
```

仍依次执行 `a()`、`b()`、`c()`，然后完成括号内加法和外层乘法。

## 13. 确认结论

Ink 的表达式子项统一按照源码从左到右求值。调用先求值被调用对象，实参从左到右；索引先基础后索引；聚合元素从左到右；条件和短路运算只执行需要的分支。赋值沿用“目标位置、右侧、写入”的顺序，编译期与运行时完全一致。优化只能在不改变任何可观察结果时重排。
