# 议题 43：可重复等待的 `Task` 与结果约束

> 状态：已确认，议题 44、45、48—52、54—60、69 补充
> 确认日期：2026-08-02

## 1. 本议题的范围

本议题确定异步任务完成状态与返回值之间的语言级最低契约：

- `Task::<T>` 默认允许重复 `await`；
- 完成状态不会因为第一次 `await` 被消费；
- 按值任务结果要求 `T: Copy`；
- 不可复制资源通过原始指针或未来的显式拥有型指针返回；
- `Task::<T>` 本身不可复制；
- 任务只有尚未执行、正在执行和成功完成三类状态；
- 可恢复的业务错误由函数签名中的普通返回值或状态表达。

异步函数声明语法、协程帧布局、运行时调度机制、组合等待和取消请求 API 由其他议题确定。

## 2. 任务保存不可逆的完成状态

`Task::<T>` 至少具有以下逻辑状态：

```text
TaskState::<T> =
    created
    pending
    succeeded(ResultStorage::<T>)
```

议题 44 将 `created` 定义为尚未执行的惰性状态。任务通过第一次直接 `await`、议题 45 的 `await all(...)` 或库使用的底层任务驱动协议从 `created` 进入 `pending`，再转换为 `succeeded`。`Task::<T>` 不提供公开的 `start()`。完成状态发布后不可重新写回、替换或恢复为 `pending`。

结果在发布后只读。状态发布必须与所有等待者同步，使等待者能够看到任务完成前对结果存储所做的初始化。

议题 48 确定取消只是一项协作式请求，不增加独立终态。任务响应请求后仍通过普通返回进入 `succeeded`；需要区分取消、业务错误或正常结果的 API，必须把这种区别编码在它公开的返回类型中。

## 3. `Task::<T>` 默认可重复 `await`

对同一个已完成任务重复 `await` 是合法操作：

```ink
var task = load_async();

const first = await task;
const second = await task;
```

第一次 `await` 不会：

- 使 `task` 绑定失效；
- 从任务中取走完成状态；
- 把任务变成“已经移动”或“已经观察”的特殊状态；
- 阻止后续等待者读取同一终态。

这与议题 02 不提供通用移动语义的规则一致。`await` 观察任务的终态，不消费任务变量。

如果任务仍处于 `created`，第一次直接 `await` 或组合等待还负责只驱动一次函数体；后续等待者不会重新执行任务。

## 4. 结果按普通复制规则返回

对于非 `void` 的按值任务结果，`T` 必须满足 `Copy`。每次 `await` 都按照议题 02 的普通复制规则，从任务的只读结果存储构造当前表达式结果：

```ink
var task: Task::<int> = calculate_async();

const first: int = await task;
const second: int = await task;
```

这种复制不能隐藏内存分配、引用计数修改、用户复制函数、资源复制或其他可能失败的操作。

`Task::<void>` 不包含结果载荷，不受 `T: Copy` 约束。普通引用、原始指针和原始切片只要满足结果复制要求，都可以作为任务结果；它们不拥有目标，目标生命周期由程序员负责。安全切片仍使用自己的不逃逸规则，不能作为长期任务结果。

## 5. 不可复制结果通过指针表达

`Task::<T>` 不因为异步返回而为不可复制类型引入隐藏移动：

```ink
var invalid: Task::<File>;  // 编译错误：File 不可复制
var valid: Task::<File*>;   // 合法：复制并返回原始指针
```

重复等待 `Task::<File*>` 返回相同的指针值，不复制 `File`，也不使第一次取得的指针失效。

`File*` 仍然是非拥有指针。任务销毁不会仅因结果类型是 `File*` 而销毁 `File`；创建者或库定义的其他拥有者必须保证目标对象存活。未来的显式拥有型指针可以作为另一种任务结果，但其所有权交接规则必须单独设计，不能通过 `Task::<T>` 隐式引入移动。

## 6. `Task::<T>` 本身不可复制

默认 `Task::<T>` 是不可复制的运行时对象。概念声明为：

```ink
[noncopyable]
class Task<T: type>
{
    // 运行时私有状态
}
```

异步调用可以利用议题 02 的保证原地构造，直接在接收位置建立任务对象：

```ink
var task = load_async();
```

把 `Task::<T>` 赋给另一个命名变量、按值传参或存入 `Vector::<Task::<T>>` 是编译错误。需要从其他位置长期访问同一任务时使用 `Task::<T>*`，并由指针使用者保证任务对象生命周期。核心语言不定义共享任务句柄，库可以在现有生命周期规则上提供显式包装。

“任务可被重复等待”只描述同一任务对象的终态观察能力，不代表任务句柄可以隐式复制。

议题 60 规定任务结果类型不参与方差转换。`Task::<Derived*>` 与 `Task::<Base*>` 是两个不兼容的具体任务类型；继承指针转换必须在异步函数发布结果前完成。

议题 69 的元组结果按照元素组合复制能力。包含普通引用的元组可以作为任务结果，任务只保存和复制非拥有别名；程序员必须保证每次 `await` 使用结果时目标仍然有效。

## 7. 显式业务状态

异步函数与普通函数使用相同的显式返回约定。操作可能无法完成时，API 可以返回状态枚举、带标签联合、可空指针或项目定义的其他普通结果类型：

```ink
enum LoadStatus
{
    ready(Config*),
    unavailable,
}

async fn load_config() -> LoadStatus
{
    // 所有结果都通过普通 return 发布。
}
```

`await` 只取得这个普通值，不改变其含义，也不会为其中某个枚举项触发隐式控制流。调用者使用枚举判别与访问 API 显式处理各个状态。

宿主内存耗尽、运行时状态损坏等无法可靠恢复的进程级故障仍按议题 01 的致命错误规则处理，不会转换成任务返回值。

## 8. 并发等待

在任务对象和结果指向对象的生命周期前置条件得到满足时，不同线程或任务可以同时等待同一个 `Task::<T>`：

- `pending` 状态可以登记多个 continuation；
- 完成时唤醒所有已登记等待者；
- 每个等待者各自复制只读的 `T`；
- 一个等待者的后续控制流不改变其他等待者看到的结果。

通过原始 `Task::<T>*` 跨线程访问时，程序员仍负责目标任务对象没有被并发销毁，并满足地址与同步前置条件。议题 51 规定析构 `pending` 任务触发致命 trap；请求取消不能代替等待任务结束。

## 9. 成本模型

任务的第一次 `await` 可能需要执行一次 `created` 到 `pending` 的原子状态转换、安排运行并登记 continuation。任务完成时需要发布结果并唤醒等待者。

已完成任务的每次 `await` 至少需要完成状态同步和一次普通 `T` 复制。复制成本受 `T: Copy` 限制，不执行隐藏分配、引用计数或用户代码。

这些成本只由显式创建和等待任务的代码承担，不添加到普通同步函数调用、对象赋值或未使用异步功能的路径。

## 10. LLVM 与运行时实现

该设计不要求修改 LLVM 源码。Ink 可以使用 LLVM coroutine intrinsics，或由前端直接生成等价状态机。任务状态、结果存储、一次性驱动门和等待者同步由 Ink 运行时负责。

概念流程如下：

```text
async call
    → construct created task
first driver
    → atomically transition created to pending
task return
    → initialize ResultStorage::<T>
    → publish succeeded
await
    → wait for succeeded
    → copy the stored result
```
