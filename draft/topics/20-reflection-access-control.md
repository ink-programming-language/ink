# 议题 20：反射访问权限与封装

> 状态：已确认，议题 34、61、66 补充  
> 确认日期：2026-08-01

## 1. 结构可见与值访问分离

Ink 编译期反射可以查看全部声明的结构信息，包括私有类型、私有字段和私有函数的：

- 名称和声明种类；
- 类型、参数和返回类型；
- 可见性；
- 大小、对齐、字段偏移和调用约定；
- 内建属性和用户反射元数据。

能够查看这些信息不自动授予读取、修改或调用对应私有成员的权限。

```ink
comptime {
    const field = reflect(Account).field("balance");

    print(field.name);       // 允许：查看结构信息
    print(field.visibility); // 允许：得知它是 private

    field.get(account);      // 是否允许由访问上下文决定
}
```

## 2. 编译期值访问遵守普通可见性

编译期反射生成的字段读取、字段写入和函数调用遵守普通源码访问控制。

- 类型的定义模块可以通过反射操作该类型的私有成员；
- 其他模块只能操作正常可访问的成员；
- 反射不会把私有声明自动变成公开声明；
- 能够得知字段偏移不等于得到绕过访问控制的语言级字段引用。

```ink
// account.ink，Account 的定义模块
func serialize_internal(value: const Account&) {
    comptime for (const field in reflect(Account).fields) {
        serialize(field.get(value)); // 允许访问本模块私有字段
    }
}
```

外部通用序列化库即使能够枚举 `Account` 的私有字段，也不能读取其值，除非字段本来公开，或者类型通过动态反射显式暴露该字段。

## 3. 权限按词法定义上下文判断

反射操作的权限由执行该操作的代码所在的词法模块决定，不由调用者、泛型实例化位置或宏展开目标的位置决定。

```ink
// external_serializer.ink
func serialize_all<T: type>(value: const T&) {
    comptime for (const field in reflect(T).fields) {
        serialize(field.get(value));
    }
}
```

即使 `serialize_all[Account]` 在 `Account` 的定义模块中实例化或调用，函数体仍属于 `external_serializer`，不能借用调用者权限读取 `Account` 的私有字段。

装饰器生成的代码默认继承装饰器定义模块的权限，而不是被装饰目标模块的权限。否则外部装饰器可以通过附着到目标声明来提升权限。未来如需由目标类型显式授权装饰器，必须设计独立的能力授予机制。

议题 61 的编译期类型和声明构造遵循相同规则。生成声明不能通过把输出位置选在另一个模块而取得该模块的私有访问权限；权限由执行生成逻辑的词法定义模块决定，生成结果还必须通过正常的访问检查。

议题 66 的开放泛型声明句柄也不携带可转授的私有访问能力。外部高阶泛型接收句柄后仍按自身词法权限操作；完整反射能够看到私有泛型声明的参数结构，不代表可以实例化、调用或把它公开转发。

## 4. `[reflect]` 是显式动态暴露

在私有字段或私有函数上添加 `[reflect(...)]`，表示定义者明确允许通过动态反射适配器访问该成员。

```ink
[reflect]
class Player {
    [reflect(DisplayName("Health"))]
    private var health: i32;

    [reflect]
    private func reset_health() {
        health = 100;
    }
}
```

这允许运行时反射系统：

- 读取 `health`；
- 在字段可变时写入 `health`；
- 调用 `reset_health`；
- 枚举这些成员及其元数据。

它不改变普通源码的可见性：其他模块仍不能直接写 `player.health` 或直接调用 `player.reset_health()`。

未添加 `[reflect]` 的私有成员不进入动态反射表，不能通过名称、偏移猜测或通用动态访问 API 操作。

## 5. 可变性仍然有效

反射访问权限不能绕过类型和对象的可变性规则。

- `const` 字段不能通过动态反射写入；
- 通过 `const T&` 获得的接收对象不能用于修改字段；
- 字段类型本身的构造、复制和 `[noncopyable]` 规则仍然有效；
- 取得字段引用不会延长对象生命周期；目标失效后继续访问由程序员负责并可能产生 UB；
- 反射不能把只读内存转换成可写内存。

动态适配器必须检查这些条件并抛出结构化反射异常，不能通过内部 `ptrcast` 或字段偏移计算绕过它们。

## 6. 维护类型不变量

直接反射一个可变私有字段意味着定义者允许外部动态工具在字段类型允许的范围内修改它。语言不会自动理解更高层的不变量。

如果字段只能通过验证逻辑修改，应隐藏字段并反射访问函数：

```ink
[reflect]
class Account {
    private var balance: i64;

    [reflect]
    func get_balance() -> i64 {
        return balance;
    }

    [reflect]
    func set_balance(value: i64) -> bool {
        if (value < 0) {
            return false;
        }

        balance = value;
        return true;
    }
}
```

用户元数据不能改变编译器访问语义。例如自定义 `ReadOnly()` 只是一段供编辑器或框架理解的数据，不能让编译器自动禁止写入。需要语言强制只读时，应使用 `const` 字段，或者只反射 getter 而不反射底层字段。

## 7. 运行时反射不是安全边界

`[reflect]` 控制语言提供哪些动态适配器和描述符，但它不是进程内的安全沙箱。能够执行任意本机代码的组件仍可以使用裸指针、调试接口或外部系统能力访问进程内存。

反射权限的目标是维护语言封装、工具行为和可诊断性，而不是防御不可信本机代码。不可信插件需要进程隔离、能力系统或其他安全机制。

## 8. 诊断

当编译期反射代码试图越权操作私有值时，编译器必须产生错误，并同时指出：

- 被访问的私有声明；
- 反射操作的词法定义位置；
- 拒绝访问所依据的模块边界；
- 可以由类型作者采取的显式方案，例如公开访问函数或添加动态 `[reflect]`。

当运行时动态访问因为可变性、接收对象类型或模块版本不匹配而失败时，适配器抛出结构化反射异常，不产生 UB。

## 9. 不授予的能力

本议题不允许反射：

- 读取未初始化字段；
- 在目标生命周期已经结束后通过反射引用访问对象；
- 修改 `const` 对象；
- 调用已卸载模块版本的函数；
- 访问未生成动态描述符的私有成员；
- 获得函数体 AST 或局部变量；
- 把用户元数据解释成编译器访问控制指令。
