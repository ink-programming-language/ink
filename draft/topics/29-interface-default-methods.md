# 议题 29：接口默认方法与冲突消解

> 状态：已确认，议题 30、56、65 补充  
> 确认日期：2026-08-02

## 1. 接口方法可以具有默认实现

接口方法没有函数体时是实现类必须满足的要求；具有函数体时是默认方法：

```ink
interface Renderable {
    func render(canvas: Canvas&);

    func is_visible() -> bool {
        return true;
    }

    func draw_if_visible(canvas: Canvas&) {
        if is_visible() {
            render(canvas);
        }
    }
}
```

实现类没有覆盖默认方法时，通过接口视图调用默认实现。实现类可以使用 `override` 显式替换它。

## 2. 接口没有实例状态

接口不能声明：

- 实例字段；
- 构造函数；
- `destructor`；
- 需要独立对象存储的状态。

因此默认方法不能直接访问实现类字段，也不能假定实现类具有某个未在接口中声明的方法。

默认方法可以：

- 访问自己的参数和局部变量；
- 调用接口中声明的其他方法；
- 调用普通可见的自由函数和静态 API；
- 使用编译期常量和用户元数据；
- 返回接口签名允许的值。

## 3. 默认方法内部继续接口分派

默认方法内部调用另一个接口方法时，必须通过当前接口表动态分派：

```ink
interface Renderable {
    func render(canvas: Canvas&);

    func draw_twice(canvas: Canvas&) {
        render(canvas);
        render(canvas);
    }
}
```

如果 `Player` 实现 `render`，`draw_twice` 中的两次调用都进入 `Player.render`，而不是某个静态占位实现。

默认方法在 ABI 上接收当前接口胖引用，因此同时拥有对象地址和接口表地址，可以调用该接口的其他槽。

议题 56 规定异步默认方法在任务创建时把该胖接收者保存进任务帧。接口继承使调用点表与默认方法声明接口不同时，适配 thunk 先把接收者规范化到默认方法声明接口；函数体以后恢复时通过该规范化接口表分派其他方法。

## 4. 接口表槽

每个接口方法，无论是否具有默认函数体，都占据一个确定的接口表槽。

具体类—接口表生成规则为：

```text
类显式实现/覆盖方法： 槽 → 类方法适配 thunk
类未覆盖默认方法：   槽 → 接口默认实现 thunk
必需方法没有实现：    编译错误，不生成接口表
```

默认实现 thunk 不要求实现对象具有主 vptr，也不给对象增加隐藏字段。它通过两字接口引用工作。

异步默认方法的槽指向任务构造 thunk。该 thunk 不在调用表达式中执行默认函数体，而是建立议题 56 的惰性任务并保存规范化胖接收者。

## 5. 使用 `override`

类实现接口必需方法或覆盖默认方法时使用 `override`：

```ink
class Player : Renderable {
    override func render(canvas: Canvas&) {
        // 实现必需方法
    }

    override func is_visible() -> bool {
        // 覆盖默认方法
        return !hidden;
    }
}
```

`override` 必须匹配一个具体父类虚方法或至少一个已实现接口的方法要求。不存在匹配项、签名不兼容或调用约定不兼容时产生编译错误。

议题 65 的参数默认值与本议题的“接口默认方法体”是两个独立概念。参数默认值属于最初声明接口槽的调用契约；类实现或子接口覆盖不能添加、删除或改变它。源码调用先补全完整实参，再选择本议题规定的类实现或默认方法体。

接口实现方法不因为 `override` 自动成为具体类虚函数。是否参与类 vtable 仍由 `virtual` 体系决定；接口表可以直接指向普通类方法 thunk。

## 6. 多个相同必需方法

多个接口声明签名完全相同的方法要求时，一个类方法可以同时满足它们：

```ink
interface A {
    func reset();
}

interface B {
    func reset();
}

class Device : A, B {
    override func reset() {
        // 同时满足 A.reset 和 B.reset
    }
}
```

编译器分别在 `Device-as-A` 和 `Device-as-B` 接口表中建立槽，但两个槽可以指向同一个实现或等价 thunk。

## 7. 多个默认实现冲突

如果多个直接实现或继承得到的接口为同名、兼容签名的方法提供不同来源的默认实现，类或子接口必须显式覆盖：

```ink
interface A {
    func reset() {
        log("A");
    }
}

interface B {
    func reset() {
        log("B");
    }
}

class Device : A, B {
    override func reset() {
        // 必须明确给出类自己的行为
    }
}
```

没有显式覆盖时产生编译错误。编译器不能：

- 按接口在继承列表中的先后顺序选择；
- 按接口名称排序选择；
- 静默把两个默认实现串联；
- 因为当前只通过其中一个接口使用而忽略冲突。

## 8. 默认实现与必需方法相遇

一个接口提供默认实现，另一个接口只声明相同方法要求时，默认实现不会自动替另一个无关接口完成契约。实现类必须显式提供一个覆盖方法，使其明确同时满足两个接口。

这避免两个独立接口因为偶然使用相同名称和签名而建立隐藏语义依赖。

## 9. 签名不兼容的同名方法

不同接口包含同名但签名不同的方法时，它们是两个独立接口槽：

```ink
interface TextParser {
    func parse(value: StringView) -> Result;
}

interface BinaryParser {
    func parse(value: const byte[]) -> Result;
}
```

如果 Ink 的普通函数重载规则可以表达两个实现，类可以分别重载实现它们。两个接口表根据完整签名选择各自 thunk。

动态类反射仍遵守议题 23：同一个类的重载集合中至多有一个同名方法可以标记 `[reflect]`。接口自身的反射描述符使用各自完全限定接口名称，不发生冲突。

如果两个接口要求无法由普通类方法重载规则明确实现，编译器报告接口实现冲突。Ink v0 不为此引入隐式的接口限定方法名语法。

## 10. 直接类调用

类显式覆盖接口方法后，可以按照普通类方法语法调用该实现。

类仅继承一个无冲突默认方法时，也可以通过类值调用该方法，编译器使用对应接口默认实现：

```ink
let player = Player();
player.is_visible();
```

如果名称在多个接口之间产生冲突，类声明必须先按本议题显式覆盖，因此调用点不会依赖临时消歧规则。

类只继承一个无冲突异步默认方法时，直接类调用按照议题 56 构造对应接口视图和惰性任务。编译器可以去虚拟化该构造入口，但默认方法体内部的接口调用仍必须保留最终覆盖语义。

## 11. 反射

默认接口方法可以像必需接口方法一样添加 `[reflect]`：

```ink
[reflect]
interface Renderable {
    [reflect]
    func is_visible() -> bool {
        return true;
    }
}
```

接口 `FunctionInfo` 描述接口声明及其元数据。反射调用仍通过接口表槽：

- 类未覆盖时，槽进入默认实现；
- 类已覆盖时，槽进入类实现；
- 类实现自身只有显式 `[reflect]` 时才产生独立类方法描述符；
- 接口和类实现元数据不合并。

## 12. 热更新

只修改默认方法函数体而不改变签名时，可以更新其稳定入口，不要求改变对象布局。引用默认实现的接口表槽必须在同一事务中观察新入口。

新增、删除或改变接口方法签名仍属于议题 26 和 28 定义的接口 ABI 变化，需要新接口表版本。

冲突检查针对新版本完整接口集合重新执行。新版本引入默认方法冲突而实现类没有显式覆盖时，热更新编译失败，旧版本继续运行。

## 13. 成本模型

默认方法不为对象增加字段或 vptr。它可能生成一份可由多个实现类接口表共享的默认实现代码和适配 thunk。

通过接口视图调用默认方法与普通接口调用具有相同的接口槽分派成本。默认方法内部调用其他接口方法时，每次调用继续承担正常接口槽分派；编译器可以在保持覆盖和热更新语义时去虚拟化。
