# 议题 31：安全下转型与动态接口转换

> 状态：已确认，议题 32—34 补充  
> 确认日期：2026-08-02

## 1. `try_cast::<T>(value)`

Ink 使用编译器内建的 `try_cast::<T>(value)` 表达可能失败的安全运行时类型转换：

```ink
if (match .some(player) = try_cast::<Player&>(entity)) {
    player.use_item();
}

const player_pointer: Player* = try_cast::<Player*>(entity_pointer);
if (player_pointer != null) {
    player_pointer->use_item();
}
```

`try_cast` 不能被遮蔽或重载，不调用用户定义的构造函数，不复制对象，也不改变对象的所有权和生命周期。

目标类型只能是本议题允许的类引用、类裸指针或接口引用，不能是按值类类型。安全转换不会产生按值切片。

## 2. 失败结果

引用目标返回标准库 `Optional`：

```text
try_cast::<T&>(source)       -> Optional::<T&>
try_cast::<const T&>(source) -> Optional::<const T&>
```

Ink 不提供 `T?` 或 `T&?` 类型语法。`Optional::<T>` 由标准库使用议题 32 的普通泛型枚举实现。成功的 `Optional::<T&>` 包含指向原对象相应视图的非拥有引用，失败时为 `none`，必须按照议题 33 通过普通枚举模式解包。该 Optional 可以返回和长期保存，但不会延长目标生命周期；目标失效后继续使用其中引用属于 UB。

类裸指针目标继续使用已经可空的 `T*`：

```text
try_cast::<T*>(source_pointer) -> T*
```

源指针为 `null` 时直接返回 `null`，不读取类型信息。非空源指针上的类型检查失败也返回 `null`。

对满足源类型、地址、对齐和生命周期前置条件的输入，转换失败是普通定义行为，不是 UB，也不触发隐式异常或陷阱。

## 3. 保持 `const`

`try_cast` 不能去掉源观察路径的 `const`：

```ink
const entity: const Entity& = value;

try_cast::<Player&>(entity);       // 编译错误：去掉 const
try_cast::<const Player&>(entity); // 合法
```

裸指针目标遵守相同规则。确实需要显式去掉裸指针 `const` 时仍使用议题 11 的 `ptrcast`，并由程序员承担底层存储可写性的前置条件。

## 4. 静态转换不使用 `try_cast`

编译期已经保证成功的转换继续使用普通隐式转换：

- 派生类引用或指针到具体基类引用或指针；
- 具体类到其已实现接口的引用；
- 子接口引用到祖先接口引用；
- 增加 `const` 限定。

这些转换不返回可空结果。`try_cast` 只用于需要检查运行时动态类型或接口实现关系的方向。

如果编译器证明某个 `try_cast` 必定成功或失败，可以消除查询并直接构造对应 `Optional` 或空指针结果，但结果类型仍保持可失败形式。

## 5. 虚类引用和指针的下转型

通过具体基类引用或指针向派生类转换时，源类的对象必须具有主 vptr：

```ink
class Entity {
    virtual func update();
}

class Player : Entity {
    override func update() {
        // ...
    }
}

func inspect(entity: Entity&) {
    if (match .some(player) = try_cast::<Player&>(entity)) {
        // entity 的动态具体类是 Player 或 Player 的派生类
    }
}
```

运行时从主 vptr 关联的最小类型描述符检查目标类是否位于动态具体类的唯一具体继承链上，并计算目标子对象地址。成功结果仍引用原对象，不构造新的 `Player`。

源类及其继承链没有虚函数时，普通基类引用或指针只包含一个地址，没有可读取的动态身份：

```ink
class Base {}
class Derived : Base {}

func inspect(base: Base&) {
    try_cast::<Derived&>(base); // 编译错误：Base 不是动态类型源
}
```

Ink 不为支持这种转换而给所有普通类增加隐藏类型指针或建立全局对象地址表。需要运行时下转型的具体类层级必须已经通过虚函数选择主 vptr，或者通过接口视图携带动态类型描述符。

## 6. 接口到具体类

接口引用的接口表与创建该视图的具体实现类型描述符关联，因此即使实现类本身没有虚函数，也可以安全转换回兼容具体类：

```ink
const renderable: Renderable& = sprite;

if (match .some(sprite_ref) = try_cast::<Sprite&>(renderable)) {
    sprite_ref.set_frame(4);
}
```

成功要求接口视图的动态实现对象是目标类或其派生类，并且当前模块版本允许建立目标类视图。接口表中的适配信息负责返回正确对象地址；调用者不能假定接口引用的两个机器字可以被逐位解释为类引用。

## 7. 接口下转型和横向转换

父接口到子接口以及无继承关系接口之间的转换都使用 `try_cast`：

```ink
func inspect(reader: Reader&) {
    if (match .some(seekable) =
        try_cast::<SeekableReader&>(reader)) {
        seekable.seek(0);
    }

    if (match .some(closable) = try_cast::<Closable&>(reader)) {
        closable.close();
    }
}
```

运行时查询动态具体类的接口实现关系，并在成功时构造目标接口的两字引用：

```text
source { object, source_table }
    -> dynamic implementation descriptor
    -> target interface relation
    -> { same canonical object, target_table }
```

接口到接口转换保持议题 26 和 30 定义的规范对象地址不变；目标接口表中的 thunk 负责目标方法需要的具体父类地址调整。

议题 30 定义的子接口到祖先接口转换仍使用静态已知的祖先转换项，不需要 `try_cast`。只有反方向或横向转换需要动态查询。

## 8. 从虚类视图动态取得接口

虚类引用可以转换到只由某些动态派生类实现的接口：

```ink
func inspect(entity: Entity&) {
    if (match .some(serializable) =
        try_cast::<Serializable&>(entity)) {
        serializable.serialize();
    }
}
```

该操作从动态类描述符查询目标接口实现关系。普通无 vptr 的基类引用不能执行这种动态接口查询；具体静态类型已知实现接口时应使用普通接口转换。

## 9. 最小动态类型描述符

安全转换使用的最小描述符在语义上至少提供：

- 动态具体类的规范化完全限定名称；
- 当前布局和模块版本信息；
- 唯一具体父类链；
- 可动态转换的接口实现关系；
- 建立目标类子对象地址或目标接口表所需的调整信息。

虚类 vtable 和具体类—接口表必须能够定位相应最小描述符。目标 ABI 可以把关联指针放入表头，也可以使用以表地址为键的只读侧表；无论哪种方式都不增加对象内字段。

最小描述符不是用户可枚举的完整 `TypeInfo`，不包含字段列表、函数列表或用户元数据，也不要求加入动态反射全局注册表。

## 10. `try_cast` 不要求 `[reflect]`

类型不需要 `[reflect]` 就能参与 `try_cast`：

```ink
class InternalNode : Node, Visitable {
    // 没有 [reflect]，仍可从 Node& 或接口引用安全转换
}
```

`[reflect]` 只控制用户可见的完整运行时反射描述符、名称注册、动态字段访问和动态函数调用。如果类型同时具有 `[reflect]`，完整 `TypeInfo` 可以引用或复用最小描述符中的身份、布局版本和关系数据，但两种能力在语言层面不互相隐含。

完全动态的 `DynamicRef` 已经携带或可以定位动态反射类型描述符。对它执行强类型 `try_cast::<T&>` 时使用相同的关系检查和布局版本规则。

## 11. 名称身份和快速缓存

按照议题 22，类型的语义身份仍是规范化完全限定字符串名称。安全转换实现可以缓存：

- 驻留字符串指针；
- 名称哈希；
- 当前进程内的描述符指针；
- 模块加载代次内的紧凑索引；
- 已解析的继承或接口转换结果。

这些缓存值不是稳定 ID，不能持久化、跨进程解释或在所属模块版本卸载后继续使用。哈希碰撞时必须比较完整名称。

描述符指针相同可以作为当前有效加载代次中的快速成功路径；指针不同不能单独证明类型不同，因为热更新或不同模块边界可能存在同名描述符，必须按照名称和版本兼容规则继续判断。

## 12. 热更新和布局版本

仅有完全限定名称相同不足以让旧对象被解释为新布局。安全转换还必须验证源对象版本与目标代码所期望的布局和接口表版本兼容。

- 名称改变时，按照议题 22 视为删除旧类型并创建新类型，转换不跨名称自动成功；
- 名称相同且布局/接口 ABI 兼容时，运行时可以通过版本兼容关系建立目标视图；
- 名称相同但布局不兼容时，转换失败，除非对象已经完成迁移；
- 旧对象、旧表和最小描述符在相关借用和活动调用排空前必须保持有效。

版本号或描述符地址只服务于当前运行时兼容性检查，不构成语言级稳定类型 ID。

## 13. 与 `ptrcast` 的边界

`try_cast` 检查类型关系并在失败时返回空结果；`ptrcast` 只重解释裸指针地址位，不检查实际对象类型。

```ink
const checked: Derived* = try_cast::<Derived*>(base_pointer);
const unchecked: Derived* = ptrcast::<Derived*>(base_pointer);
```

第二种转换本身不验证 `base_pointer` 是否实际指向 `Derived`，也不计算通用的派生子对象地址。结果不满足目标对象访问前置条件时，后续访问可能产生 UB。

`ptrcast` 不接受引用或两字接口引用，因此 Ink v0 不提供从接口引用提取对象地址并跳过动态检查的内建快捷语法。

## 14. 输入有效性

`try_cast` 是类型关系检查，不是任意地址验证器。非空裸指针输入必须已经：

- 指向一个处于生命周期内的源类型对象；
- 满足源类型对齐；
- 允许读取其主 vptr；
- 满足并发访问前置条件。

对悬空、伪造、错位或错误源类型指针调用 `try_cast`，在读取动态类型信息前就已经违反普通裸指针契约，可能产生 UB。只有对有效源视图进行“不匹配目标类型”的失败才保证返回空结果。

## 15. 成本模型与裁剪

`try_cast` 不增加普通对象大小。它的成本按实际使用的能力产生：

- 虚类 vtable 或接口表到最小描述符的静态关联；
- 类型名称和当前布局版本数据；
- 具体父类链及接口实现关系表；
- 一次继承链或接口关系查询；
- 成功时的地址调整或接口表选择。

具体类单继承下转型通常查询一条短父类链；接口横向转换通常查询动态类的接口关系表。实现可以使用已验证的当前进程缓存加速，但不能改变字符串身份和热更新兼容语义。

如果整个可达程序不使用或导出安全动态转换，编译器和链接器可以省略仅为 `try_cast` 服务的关系数据。普通虚调用和接口调用不额外执行类型查询。

## 16. 后续问题

以下内容留给后续议题：

- 标准库 `Optional::<T>` 的完整便捷 API；议题 34 已确定不提供后缀 `?` 传播；
- 基于最终类和最终虚槽进行更强去虚拟化或转换静态证明的优化边界；
- 跨动态库的最小描述符 ABI 和缓存失效协议；
- 最小描述符与调试信息、异常类型信息是否共享存储；
- 拥有型动态对象和拥有型接口容器的转换 API。
