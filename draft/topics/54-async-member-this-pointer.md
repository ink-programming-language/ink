# 议题 54：异步成员函数的 `this` 是非拥有原始指针

> 状态：已确认，议题 55—57 补充异步虚函数、接口与反射  
> 确认日期：2026-08-02

## 1. 保留普通成员函数语法

Ink 允许类声明异步成员函数，不要求为异步方法额外写出 `this: Type*` 接收者参数：

```ink
class Connection {
    async func read() -> Data* {
        return this->read_impl();
    }
}
```

调用继续使用普通成员调用语法：

```ink
var first = connection.read();
var second = connection_pointer->read();
```

`connection.read()` 中隐式取得对象地址只是成员调用语义，不建立一般的 `Connection → Connection*` 隐式转换，也不能用于初始化其他指针变量。

## 2. 任务帧保存原始 `this` 指针

异步成员调用与议题 44 的普通异步调用一样，只创建惰性任务。调用时求值接收对象，并把非拥有的原始 `this` 指针保存进任务帧；函数体以后由 `await` 或底层任务驱动协议执行。

概念降低为：

```text
connection.read()
    → evaluate receiver
    → capture raw pointer &connection as this
    → construct lazy Task<Result>
    → do not execute method body yet
```

在异步成员函数体中，显式 `this` 表达式具有指向当前类对象的原始指针语义，成员访问可以写成 `this->member`。接收者的只读限定必须保留为相应的 `const Type*` 语义，降低成原始指针不能丢失可变性限制。

## 3. 不复制或延长对象生命周期

创建异步成员任务不会：

- 把完整对象复制进任务帧；
- 隐式移动 `[noncopyable]` 对象；
- 增加引用计数；
- 自动把对象分配到堆上；
- 固定对象地址或阻止其析构；
- 建立拥有型或受生命周期检查的接收者关系。

任务只保存一个普通指针值。为避免要求编译器分析方法体中最后一次 `this` 使用，语言采用统一的保守契约：接收对象必须保持在原地址并一直存活到任务到达 `succeeded` 或 `failed` 最终状态。即使某个实现当前较早停止访问 `this`，也不会缩短该公开契约。

## 4. 安全用法

接收对象覆盖任务完整执行期时，普通局部用法是合法的：

```ink
async func inspect() -> ptrsize {
    var file = File.open("data.txt");
    var task = file.size_async();

    const size = await task;
    return size;
} // task 已结束并先于 file 析构
```

这里 `file` 在 `await task` 返回前保持存活，任务最终完成后才离开作用域。

## 5. 悬空 `this` 是普通指针错误

惰性任务可以把接收者地址带出创建它的作用域：

```ink
func make_task() -> Task<ptrsize> {
    var file = File.open("data.txt");
    return file.size_async();
} // file 已析构，返回的 Task 仍保存 &file

var task = make_task();
const size = await task; // 解引用悬空 this：UB
```

错误不是“返回 `Task`”本身，也不是移动任务；返回位置可以按议题 02 原地构造任务。错误在于 `file` 早于其异步成员任务的最终状态结束生命周期，违反了第 3 节的接收者契约；任务以后通过原始 `this` 指针访问对象时会表现为悬空访问 UB。

一般原始指针规则仍允许只持有、复制或销毁悬空地址值而不访问目标。但未结束的异步成员任务额外带有“接收者存活到最终状态”的公开前置条件；对象提前结束生命周期已经使程序违反该任务契约，不要求运行时恰好在该时刻检测到错误。

## 6. 编译器只做可证明的 warning

当编译器能够从局部控制流证明接收对象早于异步成员任务最终状态结束生命周期时，应给出 warning，例如上面的 `make_task()`。

第一版不要求完整借用检查、跨函数生命周期参数或全程序任务流分析。因此：

- warning 不是合法性所必需的运行时检查；
- 缺少 warning 不代表指针一定安全；
- 通过原始指针、库调度设施或跨线程代码隐藏关系时，程序员仍负责生命周期；
- 优化构建不能因为省略 warning 而改变正确程序语义。

该 warning 遵守议题 01 的诊断定位：帮助发现可证明的代码问题，但不把所有无法证明安全的系统代码拒绝编译。

## 7. 不增加运行时悬空检查

核心任务不保存接收对象的对象身份、代数、生命周期令牌或所有者指针。运行时不会在每次恢复或成员访问前验证 `this` 是否仍然有效。

如果程序需要受检查的生命周期，可以由库使用显式拥有型指针、引用计数控制块、句柄代数或其他对象模型实现；这些成本不添加到普通异步成员调用。

## 8. 并发访问仍受内存模型约束

对象仍然存活不代表任意并发访问都合法。异步成员函数与其他线程或任务同时通过同一对象地址读写时，程序还必须满足 Ink 并发内存模型和对象自身同步契约。

未经同步的冲突访问仍可能是数据竞争和 UB。`async`、`await` 或成员调用语法不自动为接收对象加锁，也不把对象变成线程安全类型。

## 9. 与普通引用规则的关系

议题 04 允许把普通 `T&` 和 `const T&` 作为非拥有别名保存进异步任务，并由程序员保证目标生命周期。安全切片仍有自己独立的不逃逸规则。

异步成员函数的隐式接收者固定表示为原始 `this` 指针，而不是普通引用。这是成员调用与任务帧 ABI 的选择，不是为了绕过引用限制。无论任务保存原始 `this` 指针还是某个显式普通引用参数，都不会延长目标生命周期；悬空后访问属于 UB。

同步成员函数、构造函数和析构函数的既有接收者 ABI 不因本议题改变。`func ~Type()` 在源码中省略接收者，其隐式 `this` 本身只是析构期间的普通非拥有可写引用；如果程序把从它派生的引用或指针保存到对象生命周期之后，后续访问同样属于 UB。

议题 06 禁止完整对象构造完成前让 `this` 逃逸。构造函数内创建异步成员任务并把它保存到构造边界之外，同样属于 `this` 逃逸并保持编译错误；不能因为帧内表示是原始指针而绕过构造期规则。

## 10. 热更新与模块固定

非虚异步成员任务在创建时固定与任务帧匹配的方法实现和模块版本，遵守议题 44。热更新不会在第一次 `await` 时重新按名称选择另一个方法体。

固定代码版本不会固定接收对象生命周期。旧任务即使仍能调用兼容旧代码，也必须保证其 `this` 指向的对象尚未销毁，并且对象布局与被固定代码兼容。

议题 55 规定类异步虚函数在任务创建时完成动态分派，并固定所选覆盖及模块版本；第一次 `await` 不重新读取 vtable。议题 56 规定异步接口调用同样在任务创建时完成接口分派：最终类实现继续保存本议题的原始 `this`，接口默认实现则保存规范化胖接收者。议题 57 的异步反射适配器在调用点验证 `DynamicRef`，随后进入这些普通任务构造路径；任务不保存反射调用者的临时动态引用。

## 11. 成本模型

普通异步成员任务只需在帧中保存一个接收者指针；成员方法本来就需要某种接收者地址，因此本议题不要求引用计数、堆分配、生命周期表或额外原子操作。

编译器能够内联异步方法或证明接收者地址已经存在于其他帧状态时，可以合并重复存储。它不能因为生命周期是程序员前置条件，就假设一个实际已经销毁的对象仍然有效并改变原始指针 UB 之外的语义。

## 12. LLVM 与运行时实现

该设计不需要修改 LLVM 源码。前端把接收者地址作为普通指针字段写入 coroutine frame；恢复函数从帧加载该字段并生成普通成员访问。

LLVM 无需理解 `this` 生命周期，也不需要插入对象存活检查。静态 warning 由 Ink 前端的局部生命周期和任务逃逸分析产生。
