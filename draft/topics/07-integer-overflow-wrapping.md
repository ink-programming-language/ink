# 议题 07：整数溢出与回绕算术

> 状态：已确认
> 确认日期：2026-08-01

## 1. 普通整数算术回绕

Ink 的所有固定宽度整数都使用按类型位宽取模的算术语义。

对于 N 位整数，`+`、`-` 和 `*` 的结果按照模 `2^N` 回绕。该规则同时适用于：

- `i8`、`i16`、`i32`、`i64`、`i128`；
- `u8`、`u16`、`u32`、`u64`、`u128`；
- `int`、`uint`；
- 目标指针宽度的 `ptrsize`。

```ink
let unsigned: u8 = 255u8 + 1u8; // 0
let signed: i8 = 127i8 + 1i8;   // -128
```

有符号整数使用二进制补码表示，其加减乘与同宽度无符号整数具有相同的底层模运算结果，再按照有符号二进制补码解释。

普通整数溢出不是 UB，也不会在运行时产生 trap。

## 2. 一元负号

一元负号同样按照类型位宽回绕。

```ink
let minimum: i8 = -128i8;
let result = -minimum; // -128
```

对于无符号整数，一元负号表示模 `2^N` 的加法逆元：

```ink
let value: u8 = 1u8;
let result = -value; // 255
```

## 3. 编译期溢出诊断

当编译器能够确定普通算术发生回绕时，必须产生 warning，但仍按照规定的回绕语义生成程序。

```ink
let value: u8 = 255u8 + 1u8;
// warning: integer arithmetic wraps from 255 + 1 to 0
```

warning：

- 不阻止编译；
- 不改变表达式值；
- 在编译期执行和运行时代码中使用同一回绕语义；
- 可以通过项目统一的诊断控制机制升级为错误或显式关闭；
- 其具体诊断编号和控制语法留给工具链议题规定。

编译器不能因为能够静态发现回绕，就把本来合法的表达式拒绝为语言错误。

## 4. 显式回绕操作

标准库仍可提供 `wrapping_add`、`wrapping_sub` 和 `wrapping_mul` 等方法，用于表达“此处有意依赖回绕”。它们与普通运算符具有相同的数值结果，但可以抑制“编译期可确定回绕”的默认 warning。

```ink
let next = counter.wrapping_add(1);
let hash = hash.wrapping_mul(prime);
```

标准库还可以提供：

```ink
value.checked_add(other)    // 返回可选结果
value.saturating_add(other) // 饱和到类型边界
```

这些 API 不改变普通运算符默认采用回绕语义的规则。

## 5. 优化器约束

编译器和优化器不能假设有符号或无符号整数永不溢出，也不能利用整数溢出删除分支或推导不可达路径。

任何基于无溢出条件的优化都必须先由编译器证明该具体表达式不会回绕，或者来自程序中另外明确规定的契约。

## 6. 相关边界算术

以下行为由议题 08 规定：

- 整数除零；
- 有符号最小值除以 `-1`；
- 余数运算的符号；
- 移位量大于等于类型位宽；
- 带符号整数右移；
- 旋转操作。
