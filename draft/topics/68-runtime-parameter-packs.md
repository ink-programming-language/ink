# 议题 68：运行时参数包与编译期类型包一一对应

> 状态：已确认，议题 69、70 补充元组构造、展开与闭合重载；Parser 议题 29、31 确认列表展开与运行时包形参语法
> 确认日期：2026-08-02

## 1. 声明语法

运行时参数包使用尾随 `...`，并由议题 62 的编译期类型包逐项决定准确类型：

```ink
func print_all<
    Types: type...
>(
    values: const Types&...
) {
    comptime for (const index in 0 .. Types.length) {
        const T: type = Types[index];
        print(values[index]);
    }
}
```

`const Types&...` 表示：对 `Types` 中每个类型 `T` 生成一个对应的 `const T&` 参数。调用者显式提供的泛型类型数量必须与运行时包实参数量完全相同。

## 2. 不进行类型推导

议题 64 的无推导规则同样适用于运行时参数包：

```ink
print_all<i32, String>(
    &number,
    &name
); // 合法

print_all(
    &number,
    &name
); // 编译错误：缺少显式 Types
```

编译器不从 `number` 和 `name` 反推 `Types`，也不为不同实参寻找公共类型。显式类型包先完成绑定，然后每个普通实参按照展开后的准确参数类型独立检查。

## 3. 闭合后是普通固定参数函数

`print_all<i32, String>` 概念上形成：

```ink
func print_all$i32$String(
    first: const i32&,
    second: const String&
) {
    print(first);
    print(second);
}
```

运行时参数包不会产生 `Any[]`、动态类型描述数组、隐藏循环或 C varargs。Partial Evaluation 展开包访问和 `comptime for` 后，LLVM 后端只看到普通固定参数函数。

## 4. 包不是普通运行时容器

`values` 是编译器维护的异构参数序列，不是具有统一运行时元素类型的数组或切片：

- 没有一块必须连续的包存储；
- 不能把整个包转换为 `void*` 或 `Any[]`；
- 不能取得一个代表所有元素的普通运行时引用；
- 不能使用运行时整数索引取得未知类型元素；
- 不自动分配元组对象或堆内存。

`values.length` 是编译期常量，等于 `Types.length`。`values[index]` 只有在 `index` 是编译期已知且位于范围内时才合法，其准确类型由 `Types[index]` 决定。

## 5. 使用 `comptime for` 静态遍历

异构包通过编译期循环逐项展开：

```ink
comptime for (const index in 0 .. Types.length) {
    const T: type = Types[index];
    const value: const T& = values[index];
    process<T>(&value);
}
```

循环体针对每个索引分别完成名称解析、类型检查和 Partial Evaluation。某一元素不支持循环体要求的操作时，对应闭合函数实例编译失败；Ink 不使用该失败建立 SFINAE 候选。

即使写成符合 Parser 议题 25 绑定形状的运行时普通 `for (const value in values)`，该循环仍不合法，因为单个运行时循环变量无法具有随索引变化的静态类型。

## 6. 传递方式逐项应用

包形参上的普通传递形式应用到每个展开参数：

```ink
values: Types...        // 每项按值
values: const Types&... // 每项只读引用
values: Types&...       // 每项可变引用
values: Types*...       // 每项原始指针值
```

按值形式分别执行每个类型的普通复制和析构规则；任一元素不可复制时，该按值闭合实例非法。引用包继续遵守每个引用自己的生命周期和可变性规则，不因位于参数包中获得统一延长。

## 7. 空运行时参数包

空编译期类型包对应零个运行时参数：

```ink
print_all<>(); // 合法
```

闭合函数中针对包的 `comptime for` 执行零次。空包不是省略默认运行时实参，也不产生零长度运行时数组。

## 8. v0 的位置限制

一个普通函数参数列表最多包含一个运行时参数包，并且它必须位于参数列表末尾：

```ink
func valid<Types: type...>(
    prefix: StringView,
    values: const Types&...
);
```

以下形式非法：

```ink
func invalid<Types: type...>(
    values: const Types&...,
    suffix: StringView
);
```

该限制使位置实参绑定不需要回溯。运行时参数包不能声明默认值；零元素由对应编译期类型包显式为空表示。

## 9. 转发与列表展开

已有运行时参数包可以在另一个普通实参列表中使用前缀展开：

```ink
func forward<Types: type...>(
    values: const Types&...
) {
    target<...Types>(...values);
}
```

`...Types` 使用议题 62 的编译期列表展开，`...values` 按原顺序展开相应运行时实参。目标参数数量、类型和传递方式在展开后按照普通调用规则检查。

Parser 议题 29 把两者统一识别为列表级 `...expression`，并在普通调用、泛型调用和元组构造中保留独立 `ListExpansion` CST 节点。它不是普通一元表达式；运行时位置只能展开本节定义的参数包或未来明确声明可展开的结构。

包只能作为整体按原顺序展开。重新排序、筛选或重复元素应通过 `comptime for` 生成一个明确的普通调用，而不是依赖运行时包切片操作。

## 10. 签名、重载和函数值

开放声明的运行时包模式是泛型签名的一部分；函数体中的包长度条件不参与签名，不能建立同签名重载。

议题 70 规定，显式编译期类型包先绑定并把运行时包展开成固定普通参数，随后这些参数参与普通重载解析；展开体失败不能作为 SFINAE 候选移除机制。

闭合实例具有固定普通函数类型：

```ink
const entry = &print_all<i32, String>;
```

该函数值的参数是展开后的 `const i32&` 和 `const String&`，不携带开放参数包。取得开放泛型函数本身的声明句柄继续使用议题 66 的 `GenericFunctionDecl`，不能作为运行时可变参数函数指针调用。

## 11. 异步函数与任务创建

异步函数的运行时参数包在任务创建时逐项按照议题 44、54 的普通参数捕获规则处理：

- 按值元素复制进 coroutine frame；
- 原始指针按值保存；
- 普通引用按非拥有地址别名保存，包展开不会延长任何目标生命周期；
- 安全切片等具有独立不逃逸规则的类型不能因包展开绕过限制；
- 参数包本身不作为一个隐藏运行时容器保存。

闭合异步函数只有展开后的固定任务构造签名。

## 12. 反射

编译期反射开放声明时可以观察：

- 运行时参数包的位置；
- 对应编译期类型包；
- 每项使用的传递模式；
- 包必须位于尾部的约束。

反射闭合实例时看到展开后的普通参数列表，不再看到开放运行时包。动态反射只能调用已经生成的闭合实例，并按照议题 21、57 提供完整 `DynamicRef[]`；不能在运行时提交新类型序列形成另一闭合函数。

## 13. 与 `all` 的关系

议题 45 的异构 `all(task1, task2, ...)` 可以使用本议题的静态运行时参数包表示闭合调用边界。每个任务保持准确 `Task<T>` 类型，结果类型由对应编译期类型包生成。

`all` 对不可复制任务的精确按值原地构造、引用或隐藏输出位置签名，以及结果元组布局，仍由 `all` API 和元组议题确定；本议题只提供无类型擦除的固定参数展开机制。

## 14. LLVM 与成本

LLVM 不需要理解运行时参数包。前端在固定点 Partial Evaluation 中把每个闭合包展开为普通参数、普通调用和普通控制流。

除各参数本来需要的传递、复制和析构成本外，参数包机制不要求运行时计数、类型标签、堆分配或迭代分派。代码尺寸会随闭合类型序列和静态展开体增加，继续受议题 61 的实例化与生成预算限制。
