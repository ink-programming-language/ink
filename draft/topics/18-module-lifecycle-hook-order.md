# 议题 18：模块生命周期钩子排序

> 状态：已确认，议题 34、42 补充，依赖环规则待定  
> 确认日期：2026-08-01

## 1. 基本原则

模块生命周期初始化遵循从依赖到使用者、从外层到内层、从前到后的顺序；清理严格按照实际成功完成的初始化顺序逆序执行。

该规则同时用于：

- 普通程序启动和退出；
- 动态模块加载和卸载；
- 热更新中新版本的准备与旧版本的回收；
- 加载失败时的局部回滚。

## 2. 模块依赖顺序

如果模块 `A` 依赖模块 `B`，则生命周期顺序为：

```text
load:   B → A
unload: A → B
```

`A.module_load` 开始执行时，`B.module_load` 必须已经成功完成。`A.module_unload` 执行期间，`B` 及其模块全局对象仍然有效。

程序如果要求两个模块具有确定的先后关系，必须显式建立模块依赖。链接器输入顺序、目标文件顺序、文件系统遍历顺序和构建系统任务完成顺序都不构成 Ink 语义中的模块依赖。

本规则假定相关模块能够形成可排序的依赖关系。允许何种模块依赖环以及依赖环内如何初始化，留给模块系统议题决定。

## 3. 无依赖模块

彼此之间不存在依赖路径的模块没有语言保证的相对加载顺序。实现可以按任意顺序或并行加载它们，但仍须满足各自的依赖约束以及议题 17 的发布同步规则。

程序不能通过两个无依赖模块的 `module_load` 副作用观察并依赖某个固定顺序。如果共享初始化状态需要顺序，应通过模块依赖把该顺序显式表达出来；如果只需要并发安全，应使用正常的同步机制。

实现选择的无依赖模块调度顺序不改变模块内钩子的顺序。

## 4. 同一模块内的声明顺序

同一模块版本中，不同源码声明生成的生命周期钩子按声明在模块中的词法顺序加载，并按相反顺序卸载。

```ink
@first
func a() {}

@second
func b() {}
```

概念顺序为：

```text
load:   first(a) → second(b)
unload: second(b) → first(a)
```

装饰器生成的生命周期钩子以被装饰声明的位置作为自己的词法锚点，而不是以装饰器定义所在文件的位置排序。

如果一个源码模块由多个物理文件组成，必须先由模块系统定义稳定的声明合并顺序；在该规则确定之前，生命周期钩子不能依赖跨文件的隐式文件顺序。

## 5. 同一函数上的装饰器栈

同一函数上的多个装饰器按照源码从上到下执行加载钩子，从下到上执行卸载钩子：

```ink
@outer
@inner
func target() {
    // ...
}
```

```text
load:   outer.module_load → inner.module_load

call:   outer.before
            inner.before
                target body
            inner.after
        outer.after

unload: inner.module_unload → outer.module_unload
```

因此，外层装饰器的生命周期包围内层装饰器的生命周期，与函数调用时的 around 语义一致。

## 6. 完整排序键

在不存在依赖环的前提下，一个生命周期钩子的逻辑排序依次由以下关系决定：

1. 模块依赖拓扑关系；
2. 同一模块内被装饰声明的词法顺序；
3. 同一声明上装饰器从上到下的顺序。

卸载顺序不是重新计算另一套排序，而是成功加载记录的严格逆序。这样即使加载过程只完成一部分，清理顺序仍然明确。

## 7. 加载失败与回滚

只有成功完成 `module_load` 的钩子才进入已初始化栈。如果后续钩子抛出异常或模块因其他原因加载失败，运行时在模块加载边界捕获异常，并按照该栈的逆序执行对应清理。

逆序回滚清理和 `module_unload` 不允许异常逃逸。议题 42 规定这类违约直接终止进程；运行时不跳过失败清理后继续执行剩余钩子，也不把第二个异常替换成普通模块加载失败。

例如：

```text
A.load 成功
B.load 成功
C.load 失败
```

回滚顺序为：

```text
B.unload → A.unload
```

不能把未成功完成的 `C.load` 视为已经初始化，也不能调用依赖完整初始化状态的 `C.unload`。`C.load` 在报告失败前必须释放自己尚未提交、又没有交给加载上下文管理的局部资源；加载上下文中的事务式资源由运行时自动回滚。

热更新的新版本加载失败时，只回滚新版本已经完成的部分，不执行旧版本的 `module_unload`，旧版本继续对外服务。

## 8. 并行实现

实现可以并行执行没有依赖关系的模块加载，但必须表现为：

- 每个模块内部仍严格遵守词法顺序和装饰器栈顺序；
- 依赖者的钩子只能在全部依赖成功完成后开始；
- 失败回滚不会清理仍被其他已加载模块使用的共享依赖；
- 所有共享状态访问遵守 Ink 的正常并发与内存模型。

语言不保证无依赖模块之间的副作用输出顺序，因此并行实现不需要伪造全局串行顺序。
