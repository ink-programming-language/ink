# 议题 45：并发组合等待 `all`

> 状态：已确认，议题 48、50、52、62、68、69 与 Parser 议题 10、23 补充；动态任务集合属于库
> 确认日期：2026-08-02

## 1. 设计目标

议题 44 确定普通 `Task::<T>` 没有公开的 `start()`。单个直接 `await` 只驱动当前等待的任务，因此连续直接等待表达顺序执行。

Ink 使用 `await all(...)` 明确表达一组惰性任务应当并发前进，并在同一个等待点收集全部结果：

```ink
var charge = charge_card();
var save = save_order();

const (receipt, order) = await all(charge, save);
```

这里使用 Parser 议题 10、23 的不可反驳元组解构声明：`await all(...)` 只求值一次，`const` 同时作用于 `receipt` 和 `order`。需要可修改的结果绑定时可以改写为 `var (receipt, order) = ...;`，无需在每个名称前重复关键字。

不需要在 `all` 返回后再次分别等待两个任务。

## 2. 成功路径语义

`await all(first, second, ...)` 的成功路径满足：

1. 按普通表达式规则求值全部参数；
2. 使每个仍处于 `created` 的任务进入议题 44 的一次性驱动协议；
3. 允许这些任务并发前进；
4. 挂起当前任务，直到全部输入任务成功结束；
5. 按参数位置而不是完成先后顺序产生结果；
6. 使用结果元组初始化左侧绑定。

完成先后不影响结果位置：

```ink
const (slow_result, fast_result) = await all(slow(), fast());
```

即使 `fast()` 先完成，第二个返回值仍然对应第二个参数。

## 3. 异构可变参数与元组结果

`all` 接受不同结果类型的任务。概念类型为：

```text
Task::<A>, Task::<B>, Task::<C>
    → await all(...)
    → (A, B, C)
```

因此可以直接进行多绑定初始化：

```ink
const (user, config, content) =
    await all(load_user(), load_config(), load_content());
```

`all` 是核心异步组合操作。议题 62 规定其静态异构任务类型由编译期类型参数包表示，议题 68 规定运行时任务实参与该类型包一一对应并在闭合实例中展开为固定参数，议题 69 规定成功结果为同顺序的内建元组。由编译器内建还是核心库源码实现的精确形式仍可由实现议题确定；无论采用哪种实现，以上源码语义不变。

## 4. 临时任务直接保存在组合等待中

异步调用表达式可以直接作为 `all` 的参数：

```ink
const (user, content) = await all(load_user(), load_content());
```

这些临时 `Task` 必须直接构造在组合等待所拥有的稳定存储中，并至少存活到整个组合等待结束。实现不能先建立命名任务，再通过复制或隐藏移动把 `[noncopyable] Task::<T>` 放入组合对象。

当参数是已经存在的命名任务时，组合等待只访问原任务对象，不复制任务状态。精确的内部地址表示和 `all(...)` 中间对象能否脱离直接 `await` 保存，留给组合等待 ABI 确定。若实现保存普通引用或指针，它不延长目标生命周期，调用者必须保证相关任务对象和其他目标在组合等待期间有效。

## 5. 结果遵守可重复等待与复制规则

`all` 不消费命名任务。组合等待成功后，原任务仍然处于议题 43 的只读成功终态，之后仍可重复 `await`：

```ink
var first_task = calculate_a();
var second_task = calculate_b();

const (first, second) = await all(first_task, second_task);
const first_again = await first_task;
```

按值结果仍要求结果类型满足 `Copy`。`all` 从每个任务的只读结果存储产生对应值，不为不可复制结果引入隐藏移动。不可复制资源继续通过原始指针或未来显式拥有型指针返回：

```ink
const (file, socket) = await all(open_file(), connect_server());
// 结果类型可以分别是 File* 与 Socket*
```

## 6. 与顺序等待的区别

下列代码顺序执行：

```ink
const first = await load_a();
const second = await load_b();
```

下列代码允许两个任务并发前进：

```ink
const (first, second) = await all(load_a(), load_b());
```

编译器不得把前一种写法自动改成后一种，也不得根据任务看似独立而推断并发。任务之间可能通过 I/O、原始指针、外部设备或其他副作用形成源码中不可见的顺序要求。

## 7. `all` 不是后台任务机制

`all` 的边界同时是这组并发任务的等待边界。它不会把输入任务变成脱离当前控制流的后台工作，也不会把任务所有权转交给全局运行时。

议题 50 进一步确定：普通等待 `all` 时，当前任务收到取消请求不会自动向输入任务传播。需要传播时必须使用明确的传播组合关系；其与 `all` 的精确组合语法留给组合器 ABI。

因此 `all` 在返回之前，必须保证它驱动的全部输入任务都已经到达最终状态，不能让仍在运行的临时任务越过 `all` 表达式继续访问已经结束的组合存储。

真正需要长期后台运行的任务必须通过显式库级 API 建立独立的稳定存储和生命周期责任；`all` 本身不提供该功能。

## 8. 显式业务状态不改变组合等待

每个输入任务都通过普通返回值到达完成状态。`all` 不解释返回值中的业务状态，也不会因为某个状态值而自动请求取消其他任务：

- 全部输入任务都必须完成；
- 每个结果按参数位置写入结果元组；
- 状态枚举、带标签联合、可空指针或项目定义的结果值保持原样；
- 调用者在 `all` 返回后显式检查和处理这些值。

需要“某个结果满足条件后请求取消其他工作”等策略时，由库使用议题 48—50 的取消请求 API 构建显式组合器。该组合器仍必须在释放自己的组合存储前等待所有已驱动任务结束，且其策略通过普通返回类型公开。

## 9. 动态任务集合

固定参数数量的 `all(a, b, c)` 可以在编译期确定异构结果元组。循环中产生的动态数量任务还需要另一种接口，例如同质任务切片、任务集合或由任务组拥有稳定存储。

由于 `Task::<T>` 是 `[noncopyable]`，普通 `Vector::<Task::<T>>` 不合法；若容器不拥有任务值，应保存 `Task::<T>*`。如果标准库提供拥有任务的动态组合器，它必须在最终稳定存储中直接构造任务，不能依赖隐式移动。

议题 52 规定动态接口、任务组、并发数量限制以及它们的结果顺序属于库设计。核心语言不再为此增加内建 `TaskGroup` 或执行器类型。

## 10. 成本模型

相对于连续直接 `await`，`all` 可能需要：

- 为每个输入任务执行一次 `created → pending` 状态转换；
- 同时登记多个 continuation 或一个组合 continuation；
- 保存未完成计数和各个结果槽；
- 在全部任务结束时恢复当前任务；
- 按参数位置组装结果元组。

这些成本只由显式写出的并发组合承担。普通直接 `await` 不需要建立任务组，也不因为语言支持 `all` 自动分配组合控制块。

当输入数量固定且不跨线程时，编译器可以把未完成计数、结果槽和 continuation 内联进当前协程帧；不能因此改变可观察的求值顺序、结果顺序或并发边界。

## 11. LLVM 与运行时实现

该设计不需要修改 LLVM 源码。Ink 前端可以把固定参数 `all` 降低为编译器生成的组合状态机：

```text
evaluate and construct child tasks
    → drive each child exactly once
    → register completion callbacks
    → suspend parent if remaining != 0
    → each completion decrements remaining
    → last completion resumes parent
    → assemble ordered tuple
```

子任务可以使用 LLVM coroutine intrinsics 或 Ink 自有状态机。未完成计数、完成发布和跨线程恢复使用普通原子操作，或者由单线程运行时调度器提供等价串行化。

LLVM 不需要理解 `all`、结果元组或任务所有权；这些由 Ink 前端、核心库和运行时共同实现。
