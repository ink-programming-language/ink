# 议题 26：vptr、vtable 与接口胖引用 ABI

> 状态：已确认，议题 24、27—31、35、55、56 补充
> 确认日期：2026-08-02

## 1. 三种表示

Ink 区分普通类值、虚类值和接口引用：

```text
普通 class 对象：      只有显式字段和必要填充
具有虚函数的 class：   显式状态 + 一个隐藏 vptr
接口引用：             { object pointer, interface table pointer }
```

`class` 关键字本身不产生运行时多态成本。成本只在程序显式使用虚函数或接口视图时出现。

## 2. 普通类没有隐藏 vptr

一个类及其具体父类链都没有虚函数时，对象不包含 vptr：

```ink
class Point {
    var x: i32;
    var y: i32;
}
```

`Point` 的对象布局只包含 `x`、`y` 和目标 ABI 所需填充。普通方法使用静态分派。

仅仅实现接口也不要求在每个对象中保存接口表指针。接口分派信息由转换得到的接口胖引用携带。

## 3. 虚类对象具有一个主 vptr

一个类声明虚函数，或继承自已经具有虚函数的父类时，完整对象具有一个主 vptr。

```ink
class Entity {
    virtual func update(delta: f32) {
        // ...
    }
}

class Player : Entity {
    override func update(delta: f32) {
        // ...
    }
}
```

议题 24 规定无函数体的 `virtual func` 是抽象虚函数。它仍然占有稳定虚槽，但抽象类不能直接实例化；一个可实例化的具体派生类必须为其继承的全部抽象槽提供有效最终覆盖。带函数体的 `virtual func` 则直接为槽提供实现。

单一具体继承链共享该主 vptr：

- 派生类覆盖父虚函数时复用原槽位；
- 派生类新增虚函数时追加新槽位；
- 不为每一层具体父类增加第二个 vptr；
- `Base*` 和 `Base&` 仍保持单字地址表示；
- 派生到基类的指针或引用上转型由编译器进行必要地址调整。

如果一个派生类的具体父类没有虚函数，而派生类首次声明虚函数，则派生布局增加自己的主 vptr。其相对于非虚父类子对象的精确位置由 Ink 目标 ABI 规定，但整个完整对象仍只有一个主 vptr。

## 4. vptr 不是普通字段

隐藏 vptr：

- 由编译器初始化和维护；
- 不参与源码字段枚举；
- 不能通过普通成员访问取得或修改；
- 不作为用户定义复制逻辑中的字段逐字复制；
- 计入对象的 `size` 和 `alignment`；
- 在编译期布局反射中可以作为隐藏 ABI 成分观察；
- 不因 `[reflect]` 自动公开为动态属性。

复制一个可复制的虚类值时，编译器为目标完整类型建立正确 vptr，并按照议题 02 复制用户状态。禁止按值切片的规则保证不会通过复制派生值产生错误的基类动态身份。

## 5. vtable 槽位

每个虚类布局版本具有编译器生成的 vtable。语义上的槽位规则是：

1. 从具体父类继承已有虚槽及其顺序；
2. `override` 复用被覆盖方法的槽位；
3. 当前类新声明的虚函数按照确定性声明顺序追加；
4. 更深派生类重复相同规则。

抽象虚函数与带实现的虚函数使用同一槽位身份和覆盖规则；“当前没有函数体”是声明能力，不产生一个可由用户正常调用的伪实现。

除普通虚函数槽外，每个虚类 vtable 还具有议题 27 定义的动态销毁入口。每个虚类 vtable 还与议题 31 的最小动态类型描述符建立逻辑关联；该关联可以位于表头或独立只读侧表，不增加对象内字段。异常支持和调试数据是否位于同一表头或独立结构，留给相应议题及目标 ABI 确定。

用户代码不能依赖虚槽数值或直接索引 vtable。跨模块 ABI 兼容检查可以使用编译器生成的槽位签名描述。

议题 55 规定异步虚函数复用同一套槽位继承和覆盖顺序，但其槽内容是覆盖专用的任务构造 thunk，而不是首次恢复入口。该 thunk 接收隐藏 `Task::<T>` 返回存储、虚槽声明类型的接收者和普通实参，自行完成最终覆盖所需的接收者调整，并直接建立最终覆盖的惰性任务。

## 6. 接口采用两字胖引用

一个接口引用在 ABI 上由两个机器字组成：

```text
interface reference = {
    object: pointer,
    table:  pointer,
}
```

- `object` 保存完整实现对象的规范地址；具体父类调整由该接口表中的适配 thunk 完成；
- `table` 指向该具体实现类型针对该接口生成的接口表；
- 接口表按照接口声明规定的确定性方法顺序保存调用入口或适配 thunk；
- 接口调用通过 `table` 选择函数，并把 `object` 作为接收对象；
- 接口引用不拥有对象，除非未来另行定义拥有型接口容器。

接口引用的生命周期不能超过其对象和接口表所属模块版本的有效期。

按照议题 35 通过异常接口捕获时，处理器中的 `const Interface&` 使用相同的两字胖引用。异常对象由异常运行时拥有，接口引用不取得所有权；异常描述符为动态异常类选择对应接口表。

## 7. 多接口不增加对象内字段

类可以实现多个接口：

```ink
class Player : Entity, Renderable, Serializable {
    // ...
}
```

编译器可以为同一个 `Player` 生成：

```text
Player-as-Renderable interface table
Player-as-Serializable interface table
```

接口存在继承时，还可以为同一个具体类生成子接口及其各祖先接口的独立接口表。子接口表按照议题 30 保存到祖先接口表的常数时间转换项，因此从子接口引用上转型时保持 `object` 不变，只替换 `table`。

但 `Player` 对象中不因此增加两个接口表指针。转换为某个接口引用时，编译器选择对应表并构造两字胖引用。

因此：

- 对象成本不随实现接口数量线性增加；
- 每种实际使用的“具体类—接口”组合可能产生一份静态接口表；
- 接口引用比普通类指针或引用多一个机器字；
- 接口调用通常包含一次表槽间接分派。

## 8. 具体虚调用与接口调用

通过虚基类引用调用：

```text
Base&
    → 从对象主 vptr 取得 vtable
    → 读取虚槽
    → 调用最终覆盖
```

如果该槽对应异步虚函数，“调用最终覆盖”表示调用议题 55 的任务构造入口。虚派发在这里完成；函数体以后恢复时不再读取主 vptr。

通过接口引用调用：

```text
InterfaceRef { object, table }
    → 从 table 读取接口槽
    → 调用实现或适配 thunk
```

如果该槽对应异步接口方法，“调用实现或适配 thunk”表示调用议题 56 的任务构造入口。接口分派在任务创建时完成；第一次 `await` 不重新读取原始接口槽。类实现 thunk 保存调整后的原始 `this`，默认实现 thunk 保存规范化到默认方法声明接口的胖接收者。

接口实现方法不必仅因为被接口调用就成为具体类虚函数。接口表可以直接指向普通类方法的适配入口。一个方法同时是类虚函数和接口实现时，接口 thunk 必须保留普通语言最终规定的覆盖语义。类没有覆盖接口默认方法时，对应接口槽按照议题 29 指向默认实现 thunk；子接口继承、重新抽象和祖先接口转换按照议题 30 生成槽位及转换项。

## 9. 反射

`[reflect]` 不决定对象是否具有 vptr。只有虚函数语义决定主 vptr；只有转换到接口视图时才形成接口胖引用。

反射虚函数适配器按照议题 25 使用主 vtable 虚槽。接口反射调用按照议题 28 使用接口表槽。议题 31 的安全转换可以使用 vtable 或接口表关联的最小动态类型描述符，但这不要求生成完整 `[reflect]` 数据。动态反射描述符可以记录所需分派种类，但不能把 vptr、接口表指针或最小描述符指针作为持久字符串身份。

编译期反射：

- `size` 和 `alignment` 包含隐藏 vptr 的影响；
- 普通 `fields` 不返回 vptr；
- 布局检查工具可以通过专门的 ABI 布局视图观察隐藏成分；
- 接口表不属于对象字段。

## 10. FFI 与透明布局

具有 vptr 的类不具有普通 C 数据布局，不能直接作为 C ABI 记录传递，除非某个目标 ABI 明确定义兼容桥接。

`[transparent]` 类不能声明或继承虚函数，也不能具有具体父类。实现接口本身不改变对象布局，但透明类型是否允许实现接口由 `[transparent]` 的完整规范另行确定。

接口胖引用同样不是普通 C 指针。FFI 边界应使用显式的对象指针和函数表结构进行适配。

## 11. 热更新

vtable 和接口表中的可调用槽必须指向议题 16、17 和 25 所要求的可更新稳定入口，或者由等价的可原子替换槽实现。

当新旧版本的虚槽和接口槽布局兼容时，运行时可以把实现入口作为同一更新事务原子替换：

- 新调用进入新实现；
- 已经执行的旧调用可以完成；
- 反射适配器、虚槽和接口槽不会观察到混合版本。

异步虚槽的版本选择与固定必须在调用版本专用构造 thunk 之前完成，并由稳定入口、epoch、hazard pointer 或等价机制保护。构造成功后，该固定转移给 `Task::<T>`；构造失败时立即释放。这样旧版本不能在“已经选中入口、任务尚未取得固定”的窗口中被卸载。

异步接口槽遵守相同的受保护选择规则。最终类实现的任务不再使用接口表时，可以在构造完成后只保留实现代码所需固定；默认异步任务保存规范化接口表时，还必须保持该表的布局版本有效。必要固定可以跨越实现代码和接口表所属模块，精确表示由目标 ABI 决定。

以下变化属于分派 ABI 变化，不能直接把旧对象的表解释为新表：

- 增加、删除或重新排序虚函数；
- 改变已有虚函数签名或调用约定；
- 把已有虚槽从同步改为异步，或从异步改为同步；
- 改变具体父类链；
- 增加、删除或重新排序接口方法；
- 改变接口方法签名；
- 改变接口的直接父接口集合或有效方法集合。

这类更新必须产生新的布局/分派版本，并迁移对象或让旧对象继续固定旧版本；否则更新失败。仅改变槽内实现代码而不改变槽签名时不要求对象迁移。

## 12. 成本模型

```text
普通类对象：       0 个隐藏分派指针
虚类对象：         1 个隐藏 vptr
普通类指针/引用：  1 个机器字
虚基类指针/引用：  1 个机器字
接口引用：         2 个机器字
```

普通静态调用没有动态分派成本。虚调用和接口调用各自通常具有一次表槽间接调用；适配 thunk、反射检查和热更新入口可能增加额外间接层，但只在对应功能实际启用时存在。

异步虚调用只在任务创建时承担这次主 vtable 分派。后续任务恢复可以通过任务控制块的 resume 入口间接调用，但不会再次读取对象 vptr。

异步接口调用同样只在任务创建时承担原始接口槽分派。类实现任务通常保存一个接收者指针；默认实现任务通常保存两字接口胖接收者。默认方法体以后主动调用其他接口方法时仍承担那些新调用各自的接口槽分派成本。
