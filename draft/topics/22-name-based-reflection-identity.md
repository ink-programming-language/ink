# 议题 22：基于名称的动态反射身份

> 状态：已确认，议题 23、31、35、37 补充，Module 议题 01、02 确认路径身份  
> 确认日期：2026-08-01

## 1. 不提供稳定声明 ID

Ink 不提供 `[stable_id]` 属性，也不为反射声明定义需要跨重命名保持不变的持久化整数 `TypeId` 或声明 ID。

动态反射中的类型、字段、函数和元数据类型都以规范化的完全限定字符串名称作为语义身份。

```ink
if (match .some(type) = reflection.find_type("game.Player")) {
    if (match .some(property) = type.property("health")) {
        print(property.name);
    }

    if (match .some(function) = type.function("take_damage")) {
        print(function.name);
    }
}
```

源码名称就是动态反射接口的一部分。

## 2. 完全限定名称

完全限定名称必须包含足够的源码命名空间信息，避免正常加载的不同声明发生歧义。概念形式为：

```text
类型：      package.module.Player
字段：      package.module.Player.health
顶层函数：  package.module.spawn_player
成员函数：  package.module.Player.take_damage
元数据类型：package.module.Range
```

Module 议题 01 规定：包清单确定根 package 名，源码根下的子目录形成 subpackage，每个 `.ink` 文件形成一个 module。Module 议题 02 规定相对导入解析后规范化为同一绝对 module 身份。规范名称使用这一逻辑路径，而不是物理绝对路径；源码别名、局部 `import` 别名、相对导入写法和文件系统实际路径不能改变规范名称。

动态反射函数不使用签名扩展名称。议题 23 禁止同一反射作用域内出现两个同名反射函数，因此函数的完全限定名称只需要声明路径和函数名。

## 3. 查找规则

运行时全局查找使用完全限定名称：

```ink
if (match .some(type) = reflection.find_type("game.Player")) {
    print(type.name);
}

if (match .some(function) = reflection.find_function(
    "game.Player.take_damage"
)) {
    print(function.name);
}
```

已经取得 `TypeInfo` 后，可以使用成员局部名称查询：

```ink
if (match .some(health) = type.property("health")) {
    print(health.name);
}

if (match .some(damage) = type.function("take_damage")) {
    print(damage.name);
}
```

由于同一类型中不能有两个同名反射函数，局部名称可以唯一确定当前继承视图中的函数。继承链上的同名成员按照议题 23 从子类到父类查找。

反射查找默认进行精确、区分大小写的字符串匹配，不执行模糊匹配、Unicode 外观相似匹配、自动命名风格转换或历史名称回退。

## 4. 重命名语义

任何进入完全限定名称的组成部分发生变化，都视为删除旧声明并创建新声明，包括：

- 包或模块重命名；
- 类型重命名；
- 字段重命名；
- 函数重命名；
- 元数据类型重命名。

编译器和运行时不自动建立别名，也不尝试通过源码位置、结构相似度或旧构建信息推断新旧声明是同一个实体。

## 5. 热更新

热更新注册表使用完全限定名称匹配新旧声明：

- 名称相同：作为同名声明的新版本进入兼容性和布局检查；
- 名称不同：新名称作为新声明注册，旧名称按照旧声明卸载；
- 旧名称在旧版本调用和对象排空前仍可保留在旧版本视图中；
- 新查询只观察事务提交后的当前名称表。

名称相同不代表布局兼容。议题 21 规定的布局版本检查仍然必须执行。

## 6. 存档、资源和 RPC

如果程序把反射名称写入存档、编辑器资源、网络协议或 RPC 描述，源码重命名就是相应外部格式的兼容性变更。

需要兼容旧数据时，由应用显式提供迁移规则，例如：

```ink
const type_migrations = comptime [
    ("game.Player", "game.Character")
];
```

迁移表、旧名称元数据或协议版本属于应用和框架数据，编译器不把它们解释为语言级身份别名。用户可以定义 `FormerName` 等 `[metadata]` 类型供自己的工具读取，但它不会改变 Ink 反射注册表的名称规则。

## 7. 元数据查询

`metadata.get[T]()` 由编译器取得 `T` 的完全限定名称，并按照该字符串查找元数据值：

```ink
const range = property.metadata.get[editor.Range]();
```

重命名元数据类型会使旧名称成为不存在的新旧边界。运行时枚举未知元数据时必须能够返回其保存的完全限定类型名称。

## 8. 实现可以缓存，但字符串是权威身份

实现可以使用以下方式加速字符串查找：

- 字符串驻留；
- 哈希表；
- 进程内索引；
- 描述符指针；
- `TypeHandle` 或其他缓存句柄。

这些值都只是当前进程和当前加载状态中的缓存，不是语言级稳定 ID：

- 不能单独写入持久化数据；
- 不能假定下次启动具有相同数值；
- 不能在模块卸载后继续解引用；
- 哈希碰撞时必须比较完整规范字符串；
- 对外可观察的身份判断最终必须与完整名称一致。

因此 `DynamicRef` 可以保存紧凑的进程内 `TypeHandle`，不需要在每个临时引用中复制完整类型名称，也不改变本议题的字符串身份语义。

议题 37 的 `ExceptionView.type_name()` 返回活动异常描述符保存的规范化完全限定名称。该操作不要求异常类具有 `[reflect]`，也不把描述符指针或模块版本编号暴露为稳定身份；返回的安全字符串视图继承当前异常处理器的短期不逃逸限制。

## 9. 名称冲突

同一运行时反射注册表中不能同时公开两个具有相同完全限定名称、但表示不同声明的当前版本。

- 编译期可见冲突必须产生编译错误；
- 动态模块加载产生冲突时，加载事务失败且不公开部分注册；
- 同名热更新只有通过 ABI、布局和版本检查后才能替换旧版本；
- 同一作用域中的同名反射成员按照议题 23 在编译期拒绝。

## 10. 注册系统

路由、RPC 和事件系统可以采用自己的字符串语义键，例如请求方法与路径组合。加载器仍按模块版本记录注册项所有权，以保证旧版本清理不会删除新版本记录。

这些注册系统不需要声明稳定 ID。如果它们选择把源码完全限定名称作为键，同样遵守“重命名等于删除并创建”的规则。

## 11. 成本模型

字符串查找主要发生在按名称发现类型或成员时。成功查找后，程序可以使用短生命周期的描述符视图或进程内句柄继续操作，不要求每次字段访问和函数调用都重新执行全字符串查找。

这种方案省去了稳定 ID 生成、保存、重命名维护和冲突诊断机制，代价是源码重命名明确成为动态反射及其外部数据的兼容性破坏。
