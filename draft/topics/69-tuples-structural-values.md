# 议题 69：元组是内建匿名结构值类型

> 状态：已确认，议题 71 补充异构编译期元值与静态遍历，Parser 议题 07、14 确认逗号与元组表达式语法  
> 确认日期：2026-08-02

## 1. 类型和值语法

Ink 使用圆括号和逗号表示元组类型与元组值：

```ink
let value: (i32, String) =
    (10, "hello");
```

元组是语言内建的匿名结构值类型，不是标准库 `Tuple<Types...>` 类的语法糖，也不具有对象身份、继承、vptr 或隐藏堆分配。

类型和值根据语法上下文区分：

```text
(i32, String)  tuple type
(10, "hello") tuple value
```

## 2. 空元组和单元素元组

空元组使用 `()`：

```ink
let unit: () = ();
```

单元素元组必须保留尾随逗号：

```ink
let one: (i32,) = (10,);
```

`(i32)` 只是带括号的 `i32` 类型，`(value)` 只是带括号的普通表达式，不构成元组。

Parser 议题 07 规定这是尾随逗号的唯一确认例外。两个及以上元素的元组不能使用尾随逗号：

```ink
(a, b)  // 合法
(a, b,) // 非法
```

空元组 `()` 是具有一个普通值的零元素类型，不等于 `void`：

```ink
func return_unit() -> () {
    return ();
}

func no_result() -> void {
    return;
}
```

`()` 可以作为变量、字段、泛型实参和普通返回值；`void` 仍表示没有值。空元组的准确可寻址存储大小由目标布局规则决定，本议题不把“零元素”强制等同于“占用零字节”。

## 3. 结构类型身份

元组类型由规范化后的有序元素类型列表唯一确定：

```text
(i32, String) == (i32, String)
(i32, String) != (String, i32)
(i32,)        != i32
()            != void
```

不同模块中写出的相同元素类型序列表示同一个元组类型，不需要共享名义声明身份。类型别名按照普通规范化规则比较其目标元素类型。

Ink v0 不提供命名元组元素；局部绑定名称不进入元组类型身份。

## 4. 不进行隐式逐元素转换

元组不会仅因每个元素分别存在转换就自动整体转换：

```ink
let source: (i32, i32) = (1, 2);
let target: (i64, i64) = source; // 编译错误
```

调用者必须显式构造目标元组并逐项执行所需转换：

```ink
let target: (i64, i64) = (
    cast<i64>(source.0),
    cast<i64>(source.1)
);
```

元素继承、接口转换或其他可转换关系不建立元组方差。准确相同的元组类型才按普通赋值、参数和返回规则兼容。

## 5. 位置元素访问

元组元素使用从零开始的位置成员访问：

```ink
print(value.0);
print(value.1);
```

位置访问保留基础元组表达式的值类别、可变性和生命周期：

```ink
value.0 = 20;        // value 可变且元素可写时合法
let first = &value.0; // 程序员负责 value 的剩余生命周期
```

编译期已知索引也可以用于结构化元编程访问；索引必须在范围内，并在类型检查该访问前已知。普通运行时整数不能索引异构元组，因为结果无法具有一个确定静态类型：

```ink
value[index]; // index 是运行时值时编译错误
```

元组不自动提供按字段名访问、运行时迭代器或同质切片视图。

议题 71 进一步允许元组元素是 `type`、`GenericDecl`、`Identifier` 等编译期值，并允许 `comptime for` 按位置使用每项准确类型重新 elaboration 循环体。该能力不为普通运行时元组增加动态异构迭代器。

## 6. 构造、复制和析构

元组元素按照源码从左到右的顺序求值并构造。构造中途抛出异常时，只析构已经成功构造的前缀元素，并按照其构造逆序执行。

完整元组析构按照元素从右到左的顺序调用各自普通析构语义。

元组的复制能力由全部元素组合决定：

- 每个元素都可复制时，元组可复制；
- 任一元素不可复制时，整个元组不可复制；
- 复制元组按元素执行普通复制，不隐藏共享、移动或堆分配；
- 元组不能通过属性覆盖某个元素的复制限制。

```ink
let resources: (File, Socket);
```

如果 `File` 或 `Socket` 不可复制，整个 `(File, Socket)` 不可复制。原地构造和返回位置优化继续适用，但不产生通用移动语义。

## 7. 引用与其他受限元素

元组可以在普通类型规则允许的位置包含引用、原始指针、不可复制值和其他元素：

```ink
let views: (const User&, const Config&);
```

包含普通 `T&` 或 `const T&` 的元组可以存入字段、全局状态、异步任务或其他长期存储，但不会让任何目标获得更长生命周期。复制元组只复制引用别名；目标失效后继续通过元素引用访问属于 UB。包含原始指针时遵守相同的程序员生命周期责任。

议题 43 的 `Task<T>` 要求成功结果可复制。普通引用是可复制的非拥有别名，因此可以出现在任务结果元组中；安全切片或其他具有独立不逃逸规则的类型仍遵守各自限制。

## 8. 模式绑定

元组使用位置模式解构：

```ink
let (number, text) = value;
```

嵌套元组可以使用嵌套位置模式：

```ink
let (header, (left, right)) = nested;
```

模式绑定不为元组引入特殊移动。按值、只读引用或可变引用绑定继续遵守普通值类别和复制能力；引用目标生命周期由程序员负责。不可复制元素不能通过无标记按值模式被隐藏复制。

模式元素数量必须与元组元素数量完全一致。忽略元素的占位模式以及更完整的 tuple pattern 语法留给模式系统后续细化。

## 9. 编译期类型包展开

议题 62 的编译期类型序列可以在元组类型列表中使用前缀展开：

```ink
(...Types)
```

例如 `Types = [i32, String, bool]` 时，结果类型为：

```ink
(i32, String, bool)
```

空类型包展开产生 `()`，单元素类型包展开产生带有一个元素的元组类型，不会退化为元素自身。

## 10. 运行时参数包展开

议题 68 的运行时参数包可以在元组值列表中展开：

```ink
func make_tuple<
    Types: comptime type...
>(
    values: Types...
) -> (...Types) {
    return (...values);
}
```

调用：

```ink
let tuple = make_tuple<i32, String>(
    10,
    "hello"
);
```

返回类型准确为 `(i32, String)`。展开按参数包原顺序逐项构造元组；按值参数、复制限制、异常清理和返回位置构造继续使用普通规则。

`(...values)` 是元组构造列表中的展开，不把参数包先装箱成某个运行时容器。

## 11. 目标布局

元组的逻辑和物理元素顺序都按照源码顺序保持。目标布局服务在元素之间和结尾插入满足各元素对齐要求的 padding：

```text
element 0
padding as required
element 1
padding as required
...
tail padding as required
```

编译器不能为了优化静默重排元素。准确 offset、总大小、对齐以及空元组的可寻址表示由 `TargetContext` 决定，并可通过编译期布局反射观察，但不跨目标或编译器 ABI 版本承诺固定数值。

后端可以在不改变地址、别名、构造、析构和调试语义时把不可观察地址的局部元组或返回元组标量化到寄存器，不要求每个元组都实际分配连续内存。

## 12. 不属于 C ABI

默认元组不具有稳定 C ABI 表示，不能直接出现在 `extern "C"` 公开签名中：

```ink
extern "C" func invalid() -> (i32, i32); // 编译错误
```

需要二进制结构返回时，使用具有明确 `repr(C)` 的具名类型和目标 C ABI 允许的调用形式。不能仅因某个元组当前布局碰巧与 C 结构体相同就跨边界使用。

## 13. 与 `all` 的关系

议题 45 的异构组合等待按输入位置产生元组结果：

```ink
let (user, permissions) = await all(
    load_user(),
    load_permissions()
);
```

如果输入任务结果分别为 `User` 和 `Permissions`，成功结果类型准确为：

```ink
(User, Permissions)
```

零输入 `all<>` 的成功结果为 `()`。由于 `Task<T>` 结果必须可复制，组合结果元组的每个元素也必须满足相应复制约束；元组机制不为 `all` 引入隐藏移动。

## 14. 反射

编译期反射把元组报告为独立类型种类，并至少提供：

- 有序元素类型列表；
- 元素数量；
- 每个元素的目标 offset；
- 总大小和对齐；
- 组合复制和析构性质。

位置索引是元组的语义成员身份。元组没有可由用户重命名的字段声明，也没有名义完全限定类型名称。

动态反射函数如何为匿名结构元组建立类型描述身份、访问适配器和跨模块版本协议，留给动态元组反射议题；本议题不因编译期完整反射自动生成完整运行时描述表。

## 15. LLVM 与成本

LLVM 不需要理解 Ink 的结构类型身份。前端为每个规范化元组类型确定布局、生命周期操作和 ABI lowering，并可以映射为 LLVM aggregate、标量集合或目标返回约定。

元组本身不要求堆分配、运行时长度、元素标签或动态分派。主要静态成本来自闭合类型布局、逐元素生命周期代码和参数包展开后的代码尺寸。
