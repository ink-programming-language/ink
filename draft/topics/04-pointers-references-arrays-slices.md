# 议题 04：指针、引用、数组与切片

> 状态：已确认，普通引用修订为 C++ 风格非拥有别名；议题 31、32、43、44、54、61 与 Parser 议题 17、19、25、29 补充
> 确认日期：2026-08-01

## 1. 原始指针

`T*` 表示可保存、可复制的原始地址。

Parser 议题 29 规定 `*`、`&`、`[]` 和 `[N]` 作为类型后缀从左到右组合，类型内部只使用前置 `const`。Parser 议题 30 进一步允许这些复合类型作为普通表达式中的一等编译期值，并使用终止型尾链区分 `*`、`&` 与普通运算符。因此 `const T*` 表示指向只读 `T` 的指针；指针绑定自身是否可重新赋值由外层 `var` 或 `const` 声明决定，不使用 `T* const`。

- `T*` 可以为空，使用 `null` 表示空指针；
- 不使用“`T*` 非空、`T*?` 可空”的双层设计；
- 需要静态非空语义时使用标准库 `NonNull::<T>` 包装；
- 指针不拥有目标对象；
- 指针可以存入字段、全局变量和容器；
- 指针不携带生命周期、边界或对象身份元数据；
- 指针与 `ptrsize` 之间可以通过 `ptrcast` 进行显式转换；
- 指针比较按照目标地址空间中的无符号数值地址定义。

下列指针操作都不要求特殊关键字：

- 复制、赋值和传递指针；
- 与 `null` 比较；
- 指针之间比较；
- 取得对象地址；
- 显式地址转换；
- 指针算术；
- `*pointer` 解引用；
- `pointer->member` 成员访问；
- `pointer[index]` 索引访问。

Parser 议题 19 进一步规定，取地址语法始终解析为 `&unary_expression`，是否合法由语义阶段判断。`T&` 或 `const T&` 表达式结果属于可取址 place；按值临时对象不能通过 `&` 隐式获得临时存储或生命周期延长。

```ink
var pointer: File* = null;
pointer = &file;

if (pointer != null) {
    pointer->read();
}
```

访问原始指针时，程序员负责保证地址有效、范围足够、对齐正确、对象尚在生命周期内，并满足并发规则。违反这些前置条件可能产生 UB。

## 2. C++ 风格非拥有引用

`T&` 与 `const T&` 是 C++ 风格的非空、非拥有别名。这里的“C++ 风格”指生命周期模型和引用返回能力，不表示 Ink 自动继承 C++ 的全部重载、模板或临时对象规则。

- `T&` 允许修改目标；
- `const T&` 只允许读取目标；
- 调用时编译器根据形参类型绑定引用，不要求调用方写取地址符；
- 引用访问使用普通的 `.`；
- 引用本身不拥有、不复制、不移动也不延长目标对象生命周期；
- 函数可以返回 `T&` 或 `const T&`；
- 引用可以存入字段、全局、元组、枚举、闭包、异步任务和其他长期结构；
- Ink 不使用生命周期参数、借用检查器或引用来源分析证明目标仍然有效；
- 目标失效后继续通过引用访问属于 UB。

```ink
func inspect(file: const File&) {
    file.read();
}

inspect(file);
file.read(); // file 仍然有效
```

函数可以返回现有对象的引用：

```ink
func current_file() -> File& {
    return application.current_file;
}

const file: File& = current_file();
```

编译器不证明 `application.current_file` 比调用者保存的引用活得更久。程序员必须保证目标对象在每次引用访问时仍然存在且地址未失效。

即使明显返回局部对象引用，普通类型检查也不把它作为内存安全错误拒绝：

```ink
func dangling_file() -> File& {
    var file = File.open("data.txt");
    return file;
}
```

函数返回后该引用已经悬空，任何依赖目标仍然有效的访问都是 UB。编译器可以在 diagnostics 规则确定后对此类明显情况产生 warning，但 warning 不构成生命周期保证。

引用与原始指针仍有表面和类型区别：引用没有正常的 `null` 状态、不能执行指针算术、使用 `.` 访问且作为别名不能被重新指向另一个对象；原始指针可以为空、复制、重新赋值、执行允许的指针运算并使用 `->`。两者都不提供目标生命周期安全保证。

### 2.1 `Optional` 可以包含引用

Ink 不提供 `T?` 或 `T&?` 类型语法。需要表达“可能存在的引用”时，使用标准库泛型 `Optional::<T&>` 或 `Optional::<const T&>`：

```ink
const result: Optional::<File&> = try_cast::<File&>(resource);
```

- 非空内容仍遵守普通引用的非拥有和可变性规则；
- 使用成员前必须先通过 `Optional` 的显式状态查询确认存在值，再通过载荷访问 API 取得引用；
- `Optional::<T&>` 可以返回、存入字段、全局、闭包、任务或其他长期结构；
- 它不会把内部引用变成拥有型对象，也不会延长目标生命周期；
- 其中的引用失效后，解包并访问目标同样属于 UB；
- 原始指针 `T*` 仍然自身可空。

`Optional::<T>` 由标准库使用议题 32 的普通泛型枚举实现，并参与通用 niche 布局优化。普通参数绑定仍使用非空 `T&`。

### 2.2 异步成员函数的 `this`

议题 54 规定异步成员函数保留普通成员调用语法，任务帧中的隐式 `this` 继续使用非拥有原始指针表示：

```ink
var task = object.operation_async();
// task 保存 &object
```

这只是接收者 ABI 选择，不再用于绕过普通引用的逃逸禁令，因为普通引用已经允许保存进异步任务。无论任务帧保存 `this` 原始指针还是普通 `T&` 参数的地址表示，都不会延长目标生命周期；目标失效后访问属于 UB。

## 3. 固定长度数组

`T[N]` 表示直接包含 `N` 个连续 `T` 元素的固定长度数组。Parser 议题 29 允许 `N` 使用完整表达式；语义分析要求它能够在编译期求值为合法整数。规范化后的长度是数组类型的一部分。

```ink
var values: int[4] = [10, 20, 30, 40];
```

数组的对象表示只包含元素本身，不额外保存运行时长度或数据指针：

```text
sizeof(T[N]) == sizeof(T) * N
```

具体大小还必须满足类型布局与尾部填充规则。`T[4]` 与 `T[8]` 是不同类型。

数组索引必须检查边界；由于长度编译期已知，编译器可以在证明安全时消除检查。数组作为类字段或局部变量时直接内联存储元素。

## 4. 安全切片

`T[]` 表示可写的非拥有切片，`const T[]` 表示只读非拥有切片。空方括号在明确类型入口和 Parser 议题 30 的普通表达式入口中始终构造切片；若普通表达式左侧不能在编译期产生 `type`，则产生语义错误。非空 `[expression]` 由 Parser 议题 29、30 中性保存，并由语义分析区分固定数组构造、编译期集合索引与普通运行时容器索引。

切片是两个机器字的胖指针：

```text
Slice::<T> = {
    data: T*,
    length: ptrsize,
}
```

在 64 位目标上，普通切片通常占 16 字节。长度保存在每个切片值中，不存放在数组前面，也不修改被引用对象的内存布局。

```ink
var numbers: int[5] = [10, 20, 30, 40, 50];

const all: const int[] = numbers[:];
const middle: const int[] = numbers[1:4];
```

概念表示为：

```text
all    = { &numbers[0], 5 }
middle = { &numbers[1], 3 }
```

安全切片遵守以下规则：

- 不拥有元素；
- 非空切片的完整元素范围必须有效；
- 空切片的 `length` 为零，此时 `data` 可以为 `null`；
- 索引始终执行边界检查，越界产生 trap；
- 子切片不复制元素，只产生新的指针和长度；
- 复制切片值只复制指针和长度，不复制元素；
- 安全切片仍具有自己独立的不逃逸规则，不能存入长期存储；普通引用改为 C++ 风格不会自动放宽安全切片。

```ink
func sum(values: const int[]) -> int {
    var result = 0;

    for (const value in values) {
        result += value;
    }

    return result;
}
```

Parser 议题 25 规定普通 `for` 必须显式写 `var` 或 `const`，并且迭代源只计算一次、循环绑定不会隐式复制元素。上例从只读切片取得的 `value` 保持 `const int&`。从可写切片取得元素时可以保持 `int&`；外层 `const` 只让绑定不可重新赋值，不会把可写引用目标递归变成只读。确实需要独立可修改副本时必须在循环体中显式声明 `var copy: int = value;`。

## 5. 原始切片

需要长期保存“地址加长度”时，使用可复制的原始切片：

```ink
class RawSlice<T: type> {
    var data: T*;
    var length: ptrsize;
}
```

`RawSlice::<T>` 可以存入字段、全局变量、闭包和异步任务。语言不验证它指向的存储是否仍然有效。通过原始切片访问元素时，程序员负责保证地址、长度、对齐和生命周期正确。

议题 43 允许普通引用、可复制的原始指针和 `RawSlice::<T>` 作为长期任务结果。普通引用结果只保存非拥有别名并由程序员保证目标生命周期；安全切片仍不能存入 `Task::<T>` 的完成状态。不可复制资源的异步结果使用原始指针时，任务不取得指针目标的所有权。

议题 44 的惰性异步调用在创建任务时把原始指针或原始切片复制进任务帧。议题 54 的异步成员 `this` 也使用相同原始指针规则；以后才启动函数体不会自动延长其目标存储的生命周期。

```ink
func process(values: RawSlice::<int>) {
    for (const index in 0 .. values.length) {
        print(values.data[index]);
    }
}
```

这里的 `0 .. values.length` 是 Parser 议题 25 专门为 `for` 头定义的升序半开边界：包含 `0`，不包含 `values.length`。它不是普通范围表达式，不能脱离 `for ... in` 用来初始化变量或作为实参。

`index < values.length` 只证明索引没有超过记录的长度，不能证明 `data` 实际指向这么多有效元素；构造错误的 `RawSlice::<T>` 后进行访问可能产生 UB。

## 6. 数组、切片与指针的差异

| 特性 | 数组 `T[N]` | 安全切片 `T[]` | 原始指针 `T*` |
| --- | --- | --- | --- |
| 是否包含元素 | 是 | 否 | 否 |
| 是否拥有存储 | 作为值时拥有 | 否 | 否 |
| 长度 | 编译期类型的一部分 | 运行时保存在切片中 | 不保存 |
| 对象大小 | 约为 `N * sizeof(T)` | 两个机器字 | 一个机器字 |
| 子范围 | 通过生成切片表示 | 直接支持 | 可计算地址但无长度 |
| 索引检查 | 有，常可静态消除 | 有，运行时检查 | 无边界信息 |
| 能否长期保存 | 可以 | 不可以 | 可以 |
| 生命周期验证 | 对内联元素自然成立 | 通过不逃逸规则限制 | 由程序员负责 |

数组的优点是内联、紧凑、长度编译期已知并易于优化；缺点是不同长度属于不同类型，不能表示运行时长度。

切片的优点是可以用统一函数处理任意长度的数据、低成本表示子范围并进行边界检查；缺点是需要两个机器字、依赖底层对象生命周期，并且运行时索引通常需要检查。

原始指针的优点是表示最小、适合 FFI 和底层数据结构；缺点是没有长度信息，语言无法验证访问范围和生命周期。
