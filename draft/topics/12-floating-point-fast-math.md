# 议题 12：浮点语义与显式 fast-math

> 状态：已确认，fast-math 细分规则待定
> 确认日期：2026-08-01

## 1. 默认严格浮点语义

普通 `f16`、`f32` 和 `f64` 运算默认遵守严格的 IEEE 754 数值语义。

默认模式下，编译器：

- 不重新结合浮点表达式；
- 不交换会改变结果的运算顺序；
- 不假设操作数和结果不是 NaN；
- 不假设操作数和结果不是正负 Infinity；
- 不忽略正零与负零的语义差异；
- 不使用近似倒数替代规定的除法；
- 不因为启用了更高优化级别而改变上述规则。

```ink
func calculate(a: f32, b: f32, c: f32) -> f32 {
    return (a + b) + c;
}
```

编译器不能在默认模式下把它重新结合为：

```ink
a + (b + c)
```

## 2. 默认不收缩为 FMA

普通乘法和加法分别完成各自的舍入：

```ink
let result = a * b + c;
```

默认不能自动收缩成单次舍入的 fused multiply-add，因为两者可能产生不同结果。

程序需要 FMA 语义时，应显式调用标准库或内建操作：

```ink
let result = fma(a, b, c);
```

`fma` 在目标具有对应指令时可以直接降低为硬件 FMA；没有对应指令时的库实现规则留给标准库与目标支持议题规定。

## 3. NaN、Infinity 与有符号零

默认模式保留 IEEE 754 对 NaN、Infinity 和有符号零的可观察语义。

浮点比较遵守通常的 IEEE 规则：

- NaN 与任何值执行 `==` 都为 `false`，包括其自身；
- NaN 与任何值执行 `!=` 都为 `true`；
- NaN 参与 `<`、`<=`、`>`、`>=` 时结果为 `false`；
- `+0.0 == -0.0` 为 `true`，但后续运算仍可观察其符号差异。

NaN payload 的传播和 signaling NaN 不由本议题提前规定。浮点异常标志、舍入模式和 subnormal 由议题 14 规定。

## 4. 显式 `[fast_math]`

Ink 使用源码中的 `[fast_math]` 属性显式选择宽松浮点优化：

```ink
[fast_math]
func approximate(a: f32, b: f32, c: f32) -> f32 {
    return a * b + c;
}
```

在 `[fast_math]` 范围内，编译器可以按照该属性最终规定的契约执行重结合、FMA 收缩、近似运算和其他宽松浮点优化。

`[fast_math]` 是程序语义的一部分，不只是后端调优提示。API 作者必须把它可能造成的数值差异视为函数实现行为。

## 5. 编译选项不能偷偷改变语义

优化级别和构建模式不能在源码没有声明时自动启用 fast-math：

```text
-O0 / -O2 / -O3 不能改变普通浮点表达式的语义
debug / release 不能改变普通浮点表达式的语义
```

工具链可以提供帮助添加、检查或禁止 `[fast_math]` 的选项，但不能通过普通优化开关把严格运算静默改成宽松运算。

## 6. 调用与内联边界

`[fast_math]` 只影响明确处于该属性范围内的浮点操作，不自动改变被调用函数的语义。

严格函数被内联到 `[fast_math]` 函数时，其原有严格浮点操作仍必须保持严格；`[fast_math]` 函数被内联到严格函数时，其内部已经声明的宽松操作仍保留宽松语义。

因此编译器中间表示必须在单个浮点操作上保留严格或宽松标记，不能只依赖最终机器函数的一个全局开关。

## 7. 性能性质

默认严格语义通常不要求插入运行时范围检查，但会限制以下优化：

- 浮点重结合；
- 自动 FMA 收缩；
- 倒数近似；
- 基于“没有 NaN/Infinity/负零”的简化；
- 部分依赖这些变换的自动向量化。

程序可以通过显式 `[fast_math]` 主动选择更大的优化空间。
