# 议题 21：动态反射值传递与调用 ABI

> 状态：已确认，议题 22、23、25、28、34、38、57、65 补充，精确二进制布局待定  
> 确认日期：2026-08-01

## 1. 定位

Ink 的动态反射采用“编译器生成描述符与适配器，加借用型动态引用”的模型。

普通用户主要使用强类型的反射便捷 API；`DynamicRef`、参数帧和结果存储是编译器、标准库反射实现、编辑器、RPC 框架等底层代码之间的 ABI，不要求普通业务代码直接操作。

该模型的目标是：

- 不给普通对象增加隐藏对象头；
- 不为了反射复制或装箱 `[noncopyable]` 对象；
- 不要求每次字段访问或函数调用进行堆分配；
- 在动态边界检查类型和可变性；
- 让错误反射调用抛出结构化反射异常，而不是破坏内存。

## 2. 常用 API

用户侧 API 保持强类型外观：

```ink
if let .some(type) = reflection.find_type("game.Player") {
    if let .some(health) = type.property("health") {
        let value = health.get[i32](&player);
        health.set[i32](&player, 80);
    }

    if let .some(function) = type.function("take_damage") {
        let result = function.call[bool](&player, 10i32);
    }
}
```

方括号中的类型参数表达调用者期待的字段类型或返回类型。运行时描述符必须与该静态期待完全匹配。

反射 API 不默认执行数值转换、用户定义隐式构造或基于字符串的动态强制转换。需要转换时，调用者先在普通 Ink 代码中显式构造或 `cast` 到准确类型。

## 3. 借用型 `DynamicRef`

反射运行时内部使用概念上的借用型动态引用：

```ink
class DynamicRef {
    data: void*;
    type: TypeHandle;
    mutable: bool;
    // 实现还保存与借用和布局版本有关的状态
}
```

其语义是“一个带有运行时类型身份和可变性的临时引用”，而不是拥有型动态值。

`TypeHandle` 是由完全限定类型名称解析得到的进程内缓存句柄，不是可持久化的整数 `TypeId`。它可以避免每次字段访问都重新比较字符串，但其语义身份仍由议题 22 的名称决定。

`DynamicRef`：

- 不拥有被引用对象；
- 不复制对象；
- 不延长对象生命周期；
- 可以引用 `[noncopyable]` 对象；
- 不能在原对象生命周期结束后继续使用；
- 不能把只读借用提升为可变借用；
- 不能从任意地址安全伪造。

议题 38 的异常捕获绑定永久只读。即使异常类具有 `[reflect]`，从捕获引用建立的 `DynamicRef` 也只能是只读借用；`borrow_mut`、`set` 或要求可变接收者的动态调用必须拒绝，不能借助反射绕过异常载荷不可变性。

安全构造入口只接受有效的普通 Ink 引用：

```ink
let read_only = DynamicRef.from(&const_value);
let writable = DynamicRef.from(&mutable_value);
```

从裸地址建立动态引用的底层入口必须要求调用者保证地址、对齐、类型、初始化状态、生命周期和可变性契约；违反契约属于普通原始指针 UB。常用反射 API 不使用该入口。

## 4. 字段读取与借用

可复制字段可以按值读取：

```ink
let health = property.get[i32](&player);
```

`get[T]` 只在运行时字段类型与 `T` 完全一致且 `T` 可复制时成功。它执行 Ink 的普通复制，不引入隐藏移动语义。

任意字段，包括 `[noncopyable]` 字段，都可以按引用借用：

```ink
let file: const File& = property.borrow[File](&object);
let buffer: Buffer& = property.borrow_mut[Buffer](&mutable_object);
```

- `borrow[T]` 返回只读引用；
- `borrow_mut[T]` 要求接收对象可变，并返回可变引用；
- 返回引用的生命周期不能超过接收对象、字段和反射描述符视图的有效期；
- 议题 20 的可见性与动态暴露规则仍然适用。

因此反射系统不需要为了读取资源字段而复制 `File`、`Buffer` 等不可复制对象。

## 5. 字段写入

字段写入使用已有对象的普通赋值语义：

```ink
property.set[i32](&player, 80);
```

它要求：

- 属性类型与参数静态类型完全一致；
- 接收对象和字段可变；
- 该字段类型支持 Ink v0 的普通赋值；
- 访问满足议题 20；
- 对象布局版本与属性适配器兼容。

议题 06 已规定 Ink v0 不提供用户重载的已有对象赋值运算符，因此反射 `set` 也不能绕过该规则。无法普通赋值的字段应通过 `borrow_mut` 修改其内部状态，或由类型作者反射一个显式 setter 函数。

## 6. 函数参数

`FunctionInfo.call` 的强类型便捷层把接收对象和每个实参临时转换为 `DynamicRef`，并在调用者栈上组成参数数组：

```text
receiver: optional DynamicRef
arguments: DynamicRef[]
```

编译器生成的函数适配器按照函数签名检查：

- 参数数量和顺序；
- 每个参数的准确动态类型描述；
- 按值、只读引用或可变引用传递方式；
- 接收对象类型与可变性；
- 调用约定和模块版本。

议题 65 的默认实参只是普通源码直接调用的补全规则。动态反射适配器不执行默认表达式，`arguments` 必须包含完整签名要求的每个参数；参数数量不足属于结构化反射调用错误。

目标是虚函数时，适配器在完成上述检查后必须按照议题 25 进入正常虚派发，不能直接调用描述符声明位置的原始函数体。

目标是接口反射函数时，适配器按照议题 28 取得或验证接口胖引用，并通过对应接口表槽调用具体实现。

目标是异步函数时，议题 57 要求使用独立的同步任务构造 API `call_async[R]`。适配器仍在调用点验证并捕获参数，不能把临时 `DynamicRef[]` 保存到任务中；最终任务由普通静态、虚或接口任务构造入口直接建立。

按值参数按照 Ink 的普通调用规则复制到调用帧。不可复制类型不能通过反射按值传递，但可以传给对应的引用参数。引用参数直接借用原值，并保持原有生命周期和可变性限制。

动态反射调用不执行用户定义隐式构造。由于运行时查找到的签名不能给源码字面量提供编译期目标类型，调用者应使用类型后缀、显式泛型参数、构造函数或 `cast` 提供准确实参类型。

## 7. 返回值存储

动态调用不要求先生成一个返回临时对象再移动或复制。调用者为期待的返回类型提供未初始化结果存储：

```text
result: DynamicOut {
    address,
    expected_type,
    initialization_state,
}
```

适配器验证返回类型后，直接在该最终存储中构造函数结果，与普通构造函数直接初始化最终目标存储的规则一致。

- 返回 `void` 时不提供结果存储；
- 调用失败且结果尚未构造时，不运行析构；
- 调用成功后，结果归调用者所有并遵守普通 RAII；
- 返回 `[noncopyable]` 值不要求隐藏移动；
- 返回引用时，结果仍是受原返回引用生命周期限制的借用，而不是拥有对象。

`call[R](...)` 是对上述结果存储协议的强类型便捷封装。

议题 57 为异步反射增加独立的 `DynamicTaskOut`。其地址指向未初始化的最终 `Task<R>` 存储，期待类型记录逻辑结果 `R` 而不是 `Task<R>`；`call_async[R]` 通过该协议原地构造惰性任务。同步函数显式返回 `Task<R>` 时仍使用本节的普通 `DynamicOut` 和 `call[Task<R>]`。

## 8. 异常语义

来自合法反射 API 输入的以下问题必须抛出结构化反射异常：

- 类型或成员不存在；
- 接收对象类型错误；
- 参数数量、类型或传递方式错误；
- 返回类型不匹配；
- 需要可变引用但只获得只读引用；
- 尝试按值读取或传递不可复制类型；
- 字段不可写；
- 描述符、对象布局版本或模块版本不兼容；
- 目标模块已经开始卸载。

这些异常按照议题 34 的普通未检查异常规则传播，不能退化成错误偏移访问、错误 ABI 调用或 UB。只有绕过安全入口并伪造裸地址、类型或生命周期契约时，才适用 Ink 的原始指针 UB 规则。

## 9. 分配与性能

反射调用的常规路径可以只使用：

- 静态只读描述符；
- 若干固定大小的 `DynamicRef`；
- 调用者栈上的参数数组；
- 调用者提供的返回存储；
- 一次描述符查找和一次适配器间接调用。

语言和标准库不得要求每次调用都建立拥有型 `Any`、复制对象或分配堆内存。调用者主动使用动态长度容器、持久化参数包或框架级缓存时产生的分配不属于反射 ABI 的固有要求。

普通直接字段访问和直接函数调用完全不经过该路径。

## 10. 对象布局与动态类型

`[reflect]` 本身不改变对象布局。`DynamicRef.from(&value)` 由静态引用捕获类型身份和当前布局版本；对象中不需要存在隐藏 `TypeInfo*`。

已经丢失类型信息的 `void*` 不能自动恢复成安全 `DynamicRef`。需要长期携带动态类型的 `AnyRef`、接口对象或插件句柄必须在其自身 ABI 中显式保存类型身份和借用关系。

## 11. 热更新与布局版本

同一个完全限定类型名称在热更新中表示同名声明的新版本，但实际对象存储仍属于创建它的布局版本。`DynamicRef` 不能只按名称取得最新描述符后盲目使用其中的字段偏移。

实现必须让动态引用或其关联借用状态同时识别实际布局版本。反射操作只能：

- 使用与该对象布局版本兼容的描述符；
- 先通过已定义的状态迁移把对象转换到新布局；
- 或抛出版本不兼容异常。

取得描述符视图时，实现必须在借用期间固定相应模块版本，防止适配器正在执行时其代码或描述表被卸载。新旧版本的注册与切换仍遵守议题 17。

类型重命名不属于同名热更新。旧名称和新名称分别按照删除与创建处理，具体规则见议题 22。

## 12. 公共接口与底层接口

标准库应把以下接口作为普通用户首选：

```ink
property.get[T](object)
property.borrow[T](object)
property.borrow_mut[T](object)
property.set[T](object, value)
function.call[R](receiver, arguments...)
function.call_async[R](receiver, arguments...)
```

`DynamicRef`、`DynamicOut`、`DynamicTaskOut` 和原始适配器入口属于反射运行时 ABI。可以向框架作者开放，但应放在明显的底层命名空间中，普通反射代码不需要手动构造它们。
