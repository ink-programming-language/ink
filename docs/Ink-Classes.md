# Class 与对象语义

Ink 的 `class` 是名义值类型。同名但不同声明的 class 不互相转换；赋值、按值传参和返回复制成员值。解释执行、字节码和 AOT 使用同一套经过语义检查的 IR；字段位置和对象布局由目标平台布局服务决定。

## 声明与构造

```ink
class Point
{
  field X: i32;
  field Y: i32 = 2;

  func __init__(X: i32): void
  {
    this.X = X;
  }

  func __init__(X: i32, Y: i32): void
  {
    this.X = X;
    this.Y = Y;
  }

  func add(N: i32): i32
  {
    this.X = this.X + N;
    return this.X + this.Y;
  }
};

func main(): i32
{
  var P = Point(38);
  return P.add(2);
}
```

该程序返回 `42`。字段必须显式指定类型；字段可以是标量、指针、定长数组或其他完整 class。`Point(...)` 只按 `__init__` 的显式参数匹配重载，不按字段位置传参。构造函数返回 `void`，拥有隐式 `this: *Point`，可以重载；私有构造函数只允许类内部调用。未声明 `__init__` 且所有字段都有默认初始化器时，编译器生成无参 `__init__()`；空类也生成无参构造。存在无默认值字段时必须声明显式构造函数，不能回退到聚合构造。

构造实参从左到右求值一次，随后在对象存储上调用 `__init__`。字段默认初始化器按声明顺序执行，然后执行用户构造函数体；即使方法体随后覆盖该字段，其默认初始化器也会执行。默认值在定义类的词法环境中绑定名字，不捕获调用处的局部变量；默认初始化器仍由独立隐藏函数表示，不提供 `this`。没有默认值的字段必须由构造函数通过 `this.Field = Value` 整体初始化，分支必须保证每条返回路径都完成初始化。未完成初始化时不能读取该字段、调用接收者方法或传出 `this`。

`class Empty {};` 和 `Empty()` 合法。`class Node;` 发布名义身份，后续定义补全同一类型；重复完整定义报错。`field Next: *Node` 允许指针递归，直接或间接按值包含自身的布局报错。前声明期间可以通过指针引用未完成类型，但不能构造或按值嵌入。

分析结束时，所有 IR 函数签名和存储值可达的 class 都必须已补全；检查沿指针、引用、数组和字段递归，允许完整类型之间的指针循环。即使函数没有被调用，`class Node; func take(P: *Node): void {}` 也报告 `INK-S0056`，因为当前字节码和 AOT 运行时类型描述不支持永久不完整的 opaque class。未参与这些运行时类型的独立 `class Node;` 仍合法。单模块和多模块分析遵循同一规则。

CLI 的多模块入口先注册全部类身份，再解析类型导入、补全字段布局及方法签名，最后检查函数体。因此函数签名可以引用源码中后声明的 class。支持 `import library;` 后的 `library.Point`、`from library import Point;`，以及 `Outer.Inner` 形式的嵌套 class。

## 字段与存储

```ink
class Box
{
  field Position: Point;
  field Samples: [i32; 2];

  func __init__(Position: Point, Samples: [i32; 2]): void
  {
    this.Position = Position;
    this.Samples = Samples;
  }
};

func example(): i32
{
  var A = Box(Point(1, 2), [3, 4]);
  var X = &A.Position.X;
  var B = A;
  A = Box(Point(40, 2), [5, 6]);
  return *X + B.Position.Y;
}
```

该程序返回 `42`。`B` 保存赋值时的值快照；更新 `A` 不修改 `B`。整体赋值保留 `A` 的存储身份，已有字段地址仍指向相同字段并观察新值。嵌套 class 和数组也遵守此规则。指针字段复制的是指针值，多个副本仍可引用同一目标；复制指针不延长其目标的生命周期。

`Object.Field` 读取或修改对象字段，`Pointer->Field` 访问指针指向的对象。字段表达式可以继续连接字段或数组下标；可变对象的字段可以取地址。`const` 对象和值参数允许读取字段，不能修改字段或取其可写地址。字段写入和取地址要求根对象已经完整初始化；只有 `__init__` 中允许逐字段完成对象初始化。

表达式先区分值快照与可寻址存储，再降低为 `ClassInstruction`、`FieldExtractInstruction`、`FieldPointerInstruction` 和已有的 Load/Store。解释器不会把字段存储实现成彼此独立的副本。

## 方法与 this

实例方法拥有隐式可写指针接收者 `this: *当前类`，源码无需声明它。`this.Field` 和 `this->Field` 都合法；`this.other()` 调用同一对象的方法。方法签名在函数体之前登记，允许调用后定义的方法和普通运行时互递归。

所有本期方法都是可变方法：

| 接收者 | 行为 |
| --- | --- |
| 可变局部对象、嵌套字段、数组元素 | 在原存储上调用，修改可观察 |
| 可写类指针 | 使用 `->`，在指向的对象上调用 |
| 构造结果或函数返回临时值 | 先物化一次临时存储，再调用 |
| `const` 对象、按值形参 | 拒绝可变方法调用；仍可读取字段 |

接收者先于实参求值，二者都只求值一次。普通方法允许按显式参数类型重载，不能仅按返回类型重载。方法值不能脱离接收者保存为绑定方法；本期没有只读方法或静态方法。类方法作用域中不能用用户参数、局部变量或局部函数重新声明 `this`。

`public`/`private` 适用于字段和方法，默认 `public`。私有成员只能由声明它的类访问；公开 `__init__` 可以接收外部实参并在方法体内初始化私有字段。嵌套类和导入类的私有性同样检查。

## 运算符方法接口

构造与析构协议见下节；其他特殊名字遵循本节的运算符映射。

`ink/semantic/operator_method.h` 集中定义运算符到 Python 风格特殊方法名的映射，供语义查找和后续扩展复用。当前接通以下实例方法：

| 运算符 | 方法名 |
| --- | --- |
| `+`、`-`、`*`、`/`、`%` | `__add__`、`__sub__`、`__mul__`、`__truediv__`、`__mod__` |
| `&`、`\|`、`^`、`<<`、`>>` | `__and__`、`__or__`、`__xor__`、`__lshift__`、`__rshift__` |
| `==`、`!=`、`<`、`<=`、`>`、`>=` | `__eq__`、`__ne__`、`__lt__`、`__le__`、`__gt__`、`__ge__` |
| 一元 `+`、`-`、`~` | `__pos__`、`__neg__`、`__invert__` |

二元操作按左操作数的 class 查找方法，右操作数作为唯一显式参数；一元操作没有显式参数。比较方法必须返回 `bool`。没有默认逐字段比较，没有反向操作符回退或 `NotImplemented` 协议，也不会把缺少的 `__ne__` 自动改写成 `!__eq__`。

运算符调用对左操作数的**值快照**建立临时接收者。因此 `const` 对象可以参与运算，特殊方法内部修改 `this` 不会修改原来的左操作数。普通 `Object.method()` 则按上节规则修改原存储。

```ink
class Number
{
  field Value: i32;

  func __init__(Value: i32): void
  {
    this.Value = Value;
  }

  func __add__(Other: Number): Number
  {
    return Number(this.Value + Other.Value);
  }

  func __eq__(Other: Number): bool
  {
    return this.Value == Other.Value;
  }
};
```

集中映射表还保留 `__radd__`、`__rsub__` 等反向操作和 `__iadd__`、`__isub__` 等原位操作名；`operatorMethodEnabled()` 明确标记这些协议尚未启用。源码复合赋值不会默默回退到快照方法。`specialMethodName()` 和 `specialMethodEnabled()` 启用 `__init__` 与 `__del__`；`__getitem__`、`__setitem__`、`__call__`、`__bool__` 仍为普通方法名，不触发特殊协议。`&&`、`||` 不提供重载入口，保持已有短路规则；`!` 保持 bool 逻辑非。

## 析构与对象生命周期

析构函数固定为公开的 `func __del__(): void`，只有隐式 `this` 参数，不能重载或标为 `comptime`。没有用户析构函数时编译器生成默认 `__del__`。源码不能直接引用或调用 `__init__`、`__del__`，对象构造和清理由编译器安排。

- 已初始化局部变量（包括 `const`）在退出词法块时按逆序析构；提前 `return` 同样清理经过的各层作用域。返回表达式先求值，再清理局部对象。
- 构造和函数返回的临时对象在完整表达式结束时析构。用临时值初始化局部变量、字段或数组，以及直接返回临时值时，清理责任转交给接收方，不重复调用析构。未执行的短路分支不会产生析构调用。
- 按值参数和从已有对象复制出来的变量具有独立生命周期。复制仍逐字段复制，不调用 `__init__`，也没有用户复制构造或移动协议；指针字段仍为非拥有的裸指针。
- 整体赋值先计算右侧值，再清理被替换的旧对象，最后在原地址写入新值。`var A: Class;` 仅声明未初始化存储，在首次整体赋值后才需要析构。
- 析构先执行用户 `__del__` 方法体，再按字段声明的逆序析构 class 字段和数组元素；数组元素按下标逆序清理。用户析构方法体中的局部变量先于成员字段清理。

语义层在共享 IR 中显式生成初始化状态标志、分支和 `__del__` 调用，VM、持久化字节码及 LLVM AOT 消费相同清理路径。正常的作用域退出执行清理；AOT panic 或进程终止不提供异常展开。底层帧内存仍可以保留到函数返回，但对象的语言生命周期在析构后已经结束。

## Comptime 与边界

`comptime` 可构造 class、复制、读写字段、操作嵌套数组/class，以及调用实例方法。编译期方法调用仍执行同一份方法 IR，`this` 指向受控编译期存储；不会重新解释方法 AST。普通函数或 `comptime func` 可以返回 class 常量。冻结结果会递归检查字段，包含不能持久化的指针的结果不能写成编译期常量。

本期没有用户复制构造、移动、继承、interface/vtable、泛型 class、类体运行时语句、字段类型推断或 C 聚合调用 ABI。构造函数支持逐字段初始化；普通代码不能观察部分初始化对象。

## 对象内存 ABI 与裸指针

普通 class 采用顺序字段布局，没有隐藏对象头、类型 ID、引用计数或 vptr。字段按声明顺序排列，每个字段起始地址满足其目标对齐，整个对象按最大字段对齐补齐尾部；空 class 的大小和对齐均为 1。数组和嵌套 class 内联存储，数组步长包含元素的尾部填充。普通方法和运算符方法不增加实例大小。

例如当前 x64 目标上的 `class Packet { field Tag: u8; field Bits: u128; field Address: *i32; field Values: [i32; 2]; };`：

| 内容 | 字节偏移 | 大小 |
| --- | ---: | ---: |
| Tag | 0 | 1 |
| 填充 | 1 | 15 |
| Bits | 16 | 16 |
| Address | 32 | 8 |
| Values | 40 | 8 |

该对象大小 48、对齐 16。`computeTypeLayout()` 与 Core 的 `ObjectLayoutBuilder` 统一计算大小、对齐、步长和字段偏移，VM 类型表、字节码验证与 LLVM lowering 共用这些规则。AOT 还对照 LLVM DataLayout 验证标量大小和 ABI 对齐；不匹配时拒绝生成代码。当前 AOT 和持久化字节码面向本机 target，不承诺任意跨目标 ABI。

解释器中的可寻址对象和 VM 槽位都使用上述连续内存布局。每个调用帧拥有一块对齐字节区，聚合传参、返回、load/store 直接复制值字节；初始化状态独立于值保存。每个类型域中每个类只有一份共享的不可变 `ClassDesc`，存放名义身份、字段名、字段类型、偏移和子布局；实例中不重复保存描述。默认初始化器保留为每次构造执行的代码，不共享求值后的实例数据。宽整数、指针变量、指针字段以及聚合都有真实字节表示；读取生成值快照，整体赋值写回原地址。内存中的指针槽只存一个机器地址，C 可以通过 `T**` 修改它，后续 Ink 读取立即看见新地址。FFI 支持传递 `*Class`，调用方负责匹配字段偏移和对齐；按值 class 的 C 参数和返回 ABI 尚未支持。

`*T` 是一个非拥有的裸机器指针。取字段地址等于基址加字段偏移，不含对象 ID、代次或所有权信息；复制、传参、返回都只复制地址。内部 `ExecutionPlace` / `ExecutionStorageRef` 仍用于 VM 分配和清理，但不进入 Ink 指针表示。局部对象和 CString 的存储结束后，已有指针成为悬空地址，不会自动清空，也不保证报告 `ExpiredPlace`。解引用空指针、悬空指针、越界地址，或者使用不满足类型/对齐/可写性约束的地址，属于未定义行为。VM 可能对已知存储提供额外诊断，这些诊断不是裸指针契约。源码数组下标的越界检查仍保留，VM 与 AOT 都报告 `INK-E0025`。

为后续动态分派保留的布局接口包括 `TypeLayout::BaseOffset` 与 `VPtrOffset`；当前均为空，不占实例空间。未来显式支持虚函数的类可在偏移 0 放一个 vptr，普通类保持无头布局；继承初期宜限制为单一数据基类，并固定基类前缀布局。interface 引用计划采用 `{Data, Table}` 两个机器指针，接口分派表独立于对象，不为每个实现的 interface 增加实例字段。借用的 interface 引用不拥有对象；若将来支持拥有型 interface 值，必须另外定义复制、销毁和所有权协议。当前仅预留元数据和设计约束，没有实现继承、虚函数或 interface 转换/调用。

## AOT runtime 边界

对象分配、字段寻址、加载、存储和普通调用直接生成 LLVM `alloca`、`getelementptr`、`load`、`store`、`call`。`runtime.cpp` 只导出 `extern "C" ink_aot_panic(Message, Length)`：输出编译器预先生成的诊断并以失败状态结束进程。Windows 使用 `GetStdHandle`、`WriteFile`、`ExitProcess`，POSIX 使用 `write` 和 `_exit`；它不依赖 Ink Core、VM、spdlog 或 C++ 容器。失败路径的生成代码先调用 C `fflush`，保留已经发生的 C 输出副作用。

正常程序从生成的 `main` 返回，由系统 C 运行库完成退出。链接需要 `ink_aot_runtime` 和系统运行库，不再链接 `ink_core` 或 spdlog；无失败路径的优化结果可能完全没有 `ink_aot_*` 调用。VM、字节码及 AOT 的一致性覆盖有定义的程序行为，不包含非法裸指针访问的诊断结果。
