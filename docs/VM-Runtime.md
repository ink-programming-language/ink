# VM 运行时设计讨论稿

本文讨论 Ink 底层虚拟机的执行状态、栈和调用约定，作为重新设计指令的依据。下文区分已确认的方向与补充建议；建议部分尚未成为固定 ABI，也不表示运行时已经实现。

## 已确认的方向

1. VM 提供 `pc`、`bp`、`sp` 三个地址寄存器，以及隐式算术状态寄存器 `eflags`。
2. 函数参数通过栈传递。
3. 栈空间通过支持寄存器操作数的 `add` 指令调整 `sp`，基本状态变化为 `sp := sp + x`。

逻辑寄存器属于 VM 的可见执行状态，与宿主 CPU 的寄存器分配无关。解释器计算有效地址、解码操作数时使用的宿主临时变量不增加 VM 的逻辑寄存器。

[VM 内存模型与指令构建](VM-Module.md) 已提供 `MachineModule`、`MachineFunction`、`MachineBasicBlock` 和 `MachineInstructionBuilder`，用于持有和构建尚未编码的 VM 指令，并记录常量、全局数据和栈帧描述。规划中的模块链接器合并逻辑模块，再由可执行镜像发射器生成 `ExecutableFile`；这些阶段以及执行器仍待实现，本文后续的调用约定建议也不等同于已实现的执行行为。

## 寄存器与符号操作数

`register.def` 通过 `REGISTER(Kind, Encoding, Spelling)` 定义寄存器，`register.h` 据此提供底层类型为 `std::uint8_t` 的 `RegisterId`：

| 寄存器 | `RegisterId` | 编号 | 文本名称 |
| --- | --- | --- | --- |
| 帧基址 | `BP` | `0` | `bp` |
| 栈顶 | `SP` | `1` | `sp` |
| 程序计数器 | `PC` | `2` | `pc` |
| 算术标志 | `EFLAGS` | `3` | `eflags` |

寄存器值使用上述独立编号，符号引用则通过 `core::Name` 保存链接名。符号名称与寄存器编号属于不同的表示，文本用 `@name` 或 `@"escaped name"` 标识符号。EFLAGS 的编号用于识别隐式状态；当前不能将其作为普通 `r` 来源、算术目标或内存基址。

指令中的寄存器操作数读取或写入寄存器值，例如 `add64rrr` 的 `r`；地址操作数用于定位内存中的值，例如 `[bp + 16]` 或 `[@counter + 8]`。立即数可以保存数值，也可以保存符号地址值，例如 `@counter + 8`。内存模型还提供持有目标基本块指针的 `BasicBlockOperand`，跳转构建时直接引用同一函数的目标块。[VM 指令编码格式](VM-Instruction-Format.md) 规定寄存器值使用一个字节的 `RegisterId`，寄存器相对地址保存编号和有符号字节偏移；数值立即数字段宽度由操作码决定。符号地址的最终编码尚待约定，名称与偏移需要先经过解析和范围检查。可执行镜像发射器完成布局后，才把基本块目标转换为 PC 相对地址字段；文件不保存基本块宿主指针。当前字节编码器、解码器、可执行镜像发射器和运行时仍待实现。

`VMInstructionSetVersion` 的默认值为 `1.1.0`，包含 EFLAGS、CMP、跳转和 RET 的操作码约定。符号操作数的逻辑扩展没有新增 ADD 等指令操作码；其最终编码仍须由后续发射器明确。

## 算术状态与控制流

EFLAGS 使用 32 位值，当前定义 CF（bit 0）、ZF（bit 6）、SF（bit 7）、OF（bit 11），其余位保留为零。执行语义规定所有 ADD 和 CMP 隐式覆盖四位；CMP 按对应位宽计算 `LHS - RHS` 并丢弃结果。普通加载、存储、跳转和 RET 保持标志不变。`eflags.h` 仅定义类型、标志掩码和 `conditionEFlagsMask()` 所表达的依赖元数据，不实现标志值生成或条件判断。当前尚没有 VM 执行状态、执行循环或这些运行时计算函数。

跳转包括 `jmp`，以及 `je/jne`、`jb/jbe/ja/jae`、`jl/jle/jg/jge`、`jo/jno`、`js/jns`。无符号大小关系使用 CF、ZF，有符号大小关系使用 SF、OF、ZF；具体条件见 [指令编码格式](VM-Instruction-Format.md)。跳转在内存中保存非空的目标基本块指针，源块和目标块须属于同一函数；文本使用 `jne failure`、`jmp done`，支持函数内前向、后向和自引用。指令插入或块布局变化保留目标身份，调用方不需要手工维护内存中的跳转位移。

后续 `ExecutableEmitter` 生成可执行镜像时，根据最终布局将目标块转换成相对当前跳转指令起始 PC 的有符号字节位移。编码沿用通用寄存器地址形式，长度为 11 字节；条件满足时转移到 `PC + ByteOffset`，不读取目标地址处的内存，条件不满足时执行 `NextPC`。若条件分支的另一条路径需要转移到不同位置，可在其后放置一条 `jmp`。这些字节生成与执行行为尚未实现。

算术、比较和条件跳转的隐式 EFLAGS 依赖由指令元数据暴露给 lowering 和后续调度。不能把另一条写标志的指令插入 CMP 与使用其结果的跳转之间。flags 按 caller-clobbered 处理，调用方不能跨函数调用依赖原有比较结果；ABI 不隐式保存或恢复标志。

## 寄存器和栈：建议约定

建议以字节为地址、偏移和长度的单位，栈向高地址增长，`sp` 指向栈顶之后的首个空闲字节。

| 寄存器 | 建议含义 |
| --- | --- |
| `pc` | 当前指令起始位置；顺序执行成功后移至下一条指令，分支、调用和返回显式改变它。 |
| `bp` | 当前函数栈帧的固定基址；函数体内预留临时空间或准备下一次调用时保持稳定。 |
| `sp` | 当前有效栈空间的末端；有效区间为 `[StackBegin, sp)`，可用容量为 `[sp, StackEnd)`。 |
| `eflags` | 最近一次算术或比较指令产生的 CF、ZF、SF、OF，由条件跳转隐式读取。 |

现有地址偏移和地址寄存器运算使用 64 位宽度，初版运行时可以沿用这一宽度，`bp` 和 `sp` 使用完整的 64 位寄存器操作。`pc` 的写入仅由控制转移指令完成。VM 地址的数值表示不直接暴露宿主指针；宿主栈缓冲区增长或移动时，已经形成的 VM 栈地址仍应保持有效。

每次调用拥有独立的帧，因此递归调用不会覆盖上一层调用的参数和局部变量。函数内的长期槽位建议使用 `bp + 固定偏移` 访问，短期的调用准备区可以使用 `sp` 相对寻址。

## 栈空间调整：建议约定

以 `sp` 为目标的寄存器加法直接调整栈顶。下例中的 `rri` 按目标、左来源、右来源的顺序表示两个寄存器操作数和一个立即数操作数：

```text
add64rri sp, sp, 16     // 预留 16 字节
add64rri sp, sp, -16    // 回收 16 字节
```

建议写入 `sp` 时将来源立即数按有符号字节增量解释。正增量预留空间，负增量回收空间，零增量保持栈顶不变。预留的空间不初始化；回收的空间不再属于有效栈空间。

执行前按数学意义计算新的地址，检查地址计算没有溢出，且新栈顶位于 `[StackBegin, StackEnd]` 内；通过检查后一次性更新 `sp` 和 EFLAGS。成功时按两个来源的 64 位位模式计算算术标志，CF 与地址检查失败是不同的概念。例如负增量的位模式参与无符号加法时可以产生 CF，而地址调整仍然有效。普通栈调整还应保持当前活动帧和调用保存区有效，具体可回收边界仍需在调用约定中确定。失败通过显式 trap 报告，`sp` 和 EFLAGS 都保持原值。

这一规则适用于所有写入 `sp` 的指令。普通整数 `add` 仍按指定位宽回绕；更新栈顶不能先回绕，再只检查最终数值是否位于栈范围内。

函数返回时回收整个函数帧中的局部空间。函数内提前回收空间时，执行该调整的函数须保证已回收空间不再被使用。

建议按增量精确移动栈顶，不暗中取整。槽位间的对齐填充由布局方计入调整量，调用边界的对齐也由调用方保证。

## 函数调用与返回：建议约定

当前已提供零操作数 `ret` 的指令模型，执行约定采用下述保存区布局：从 `[bp]` 读取旧 BP，从 `[bp + 8]` 读取返回 PC，将 SP 恢复为返回前的 BP，再提交旧 BP 和返回 PC。全部范围和目标检查成功后才提交状态，EFLAGS 保持不变。尚未提供 CALL 指令、执行器或带立即数回收调用区的 RET 形式；本节调用过程描述用于约束后续实现。

建议参数按声明顺序从低地址向高地址排列。调用方先为返回值和全部参数预留一块调用区，再写入参数；被调用方通过自己的 `bp` 和固定偏移读取参数。参数按值传递；引用参数在栈上存放地址值，具体参数大小和对齐由函数签名及其布局规则决定。

返回值也建议通过栈传递：调用方在参数区之前预留结果槽，被调用方在返回前写入该槽。无返回值的函数不需要结果槽。这一方案可以承载标量或聚合结果，无需新增返回值寄存器。

建议调用过程在调用区之后保存旧 `bp` 和返回 `pc`，并将新 `bp` 指向这段保存区的起点。以 64 位地址和两个 8 字节保存项为例，帧形状如下：

```text
低地址
┌────────────────────────────┐
│ 调用方已有的帧空间         │
├────────────────────────────┤ ← CallBegin
│ 返回值槽及对齐填充         │
│ 参数 0、参数 1、……及填充   │
├────────────────────────────┤ ← bp（进入被调用方后）
│ 旧 bp                      │  bp + 0
│ 返回 pc                    │  bp + 8
├────────────────────────────┤ ← bp + 16
│ 被调用方局部变量、临时空间 │
├────────────────────────────┤ ← sp
│ 尚未使用的栈容量           │
└────────────────────────────┘
高地址
```

初版可以建议调用边界按 8 字节对齐；更大对齐、聚合布局和可变参数规则仍需另行确定。返回槽与参数的偏移由调用双方使用相同的签名布局计算，不依赖运行时逐个压栈的顺序。

建议的状态转换如下：

1. 调用方记录 `CallBegin = sp`，预留返回槽、参数及填充，并写入参数。此时 `sp` 位于调用区末端。
2. 调用操作验证目标和保存区容量，将旧 `bp`、下一条指令地址 `NextPC` 写入保存区，然后设置 `bp = 原 sp`、`sp = bp + 16`、`pc = 函数入口`。
3. 被调用方通过寄存器形式的 `add` 增加 `sp`，预留局部空间，使用稳定的 `bp` 定位参数和局部变量；它也可以继续准备嵌套调用。
4. 返回前，被调用方完成结果槽写入，并读取保存的旧 `bp`、返回 `pc`。返回操作将 `sp` 恢复为当前 `bp`，再恢复旧 `bp` 和返回 `pc`，由此回收保存区及全部局部空间。
5. 调用方读取或转存结果，再将 `sp` 恢复到 `CallBegin`，回收参数和结果槽。调用方须能通过自身帧布局重新定位 `CallBegin`，不能依赖调用过程保留宿主临时变量。

这一方案由被调用方回收自己的保存区和局部空间，由调用方回收调用区。栈上对象的地址可以在其存活期间传递给下一层调用；函数返回后，属于其已回收帧的地址失效，不能作为有效结果交给调用方使用。

### 两个参数和一个结果的示例

假设某函数接收两个 64 位整数并返回一个 64 位整数，调用方原先 `sp = 1024`。返回槽和两个参数依次占据：

| 区间 | 内容 | 进入被调用方后的地址 |
| --- | --- | --- |
| `[1024, 1032)` | 返回值 | `bp - 24` |
| `[1032, 1040)` | 第一个参数 | `bp - 16` |
| `[1040, 1048)` | 第二个参数 | `bp - 8` |
| `[1048, 1056)` | 旧 bp | `bp + 0` |
| `[1056, 1064)` | 返回 pc | `bp + 8` |

准备参数后 `sp = 1048`。进入函数后 `bp = 1048`、`sp = 1064`；执行 `add64rri sp, sp, 16` 后 `sp = 1080`，局部空间为 `[1064, 1080)`。返回后旧 `bp` 和返回 `pc` 已恢复，`sp = 1048`；调用方取得 `[1024, 1032)` 中的结果后，执行 `add64rri sp, sp, -24`，将 `sp` 恢复为 `1024`。

## 执行边界与失败：建议约定

`pc` 必须指向合法指令起点。解码需要验证操作码、操作数长度以及目标指令边界；普通指令成功后执行 `pc = NextPC`，调用保存的也是 `NextPC`。程序入口可以使用专用的初始调用帧，最外层返回结束执行，不将任意地址当作退出哨兵。

栈容量不足、地址运算溢出、非法访存、非法指令和无效跳转目标建议通过 VM 的显式执行结果或 trap 状态报告。trap 是 VM 的停止状态，不使用宿主 C++ 异常；失败前完成必要检查，避免只更新一部分寄存器或调用帧。退出值和错误信息的对外接口仍待运行时 API 设计确定。

可执行镜像结构验证与执行验证分开处理。现有 `ExecutableFileValidator` 不解码指令；结构验证成功不代表代码已经完成指令边界、调用约定或访存验证。
